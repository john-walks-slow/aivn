# apps/web AGENTS.md

## 职责

- `apps/web` —— 舞台演出层（P2/P3 已落地）：React 19 + vite；hash 路由（`src/router.tsx`）+ REST 客户端（`src/api.ts`，ttsPreview/polish）。

## 地图与界面约定

- `src/stage/generatedAssets.ts`（生成资产台账 + 预解码，到货才淡入）。
- `src/views/`（剧目库/Title 就绪门含「有周目则「继续（档名）」在前 / 开始新周目」/周目页 SavesView `enter/重命名/删除`/舞台外壳 StageScreen：持连接与作品集状态，视图选择是 `useState` 初始值 —— URL 上的 `?view=`/`?tab=`/`?workshop=1` 走 `stage/view.ts` 的纯函数解析）。
- **封面是 play.json 的 `cover: {kind, id}`（只认 backgrounds/cg），没有设置入口就自动取第一张背景、其次第一张插图，解析只有 `api.ts` 的 `coverUrl` 一处（剧目库与标题画面共用，指向的图被删了自动回落）；设置入口在工坊「剧目」页的封面选图里，点一张即设、可恢复自动挑选**。
- `src/ui/Icon.tsx`（lucide 图标 registry，全站交互 chrome 统一走它，`btn-icon` 图标+文字行内排；舞台侧栏底栏「退出」的出口用 `exit`（LogOut）而不是 `back`）。
- **界面铺满视口、没有画框**（`app.css` 里 `--frame`/`--frame-pad` 那层「桌面上的 16:9 窗口」已整层删掉：宽屏四周露出的深色底读起来就是一圈黑边）。
- `src/voice/`（VoiceLibrary 全屏音色库面板——**筛选全部走服务端窗口查询**：语言下拉（首项「全部语言」，默认跟随 `navigator.language`，各语言不摆计数——每个语言是各自独立的 1000 条窗口、与热门目录不同源）+ 搜索框（300ms 防抖，走**全库标题搜索**，不再匹配描述与标签）+ 卡片网格逐个试听/选用 + 右上角固定「×」关闭键、分页 60 条防 1000 张图卡顿；useVoiceCatalog 是两层状态：`catalog` 基础目录管下拉与 `nameOf`、`result` 当前窗口管网格，查询带序号防慢响应覆盖新结果，筛选失败不回落热门目录、目录外 voiceId 按 id 解析）。**面板不放标签筛选**（那排 chips 在手机上要占五六行，2026-10-10 用户裁决撤掉；标签能力仍在 `GET /api/voices?tag=` 与 `list_voices` 的 `tags`，常用词表住 core 的 `VOICE_TAG_GROUPS`）。**语言下拉的两种身份由 useVoiceCatalog 的 `effectiveVoiceLanguage` 一处说了算**：系统语言默认只是浏览起点，一有关键词就摘掉（否则英文系统的用户搜「雷姆」拿到的是「英语窗口里的雷姆」= 0 条，读到的是「搜不到」而不是「语言没选对」）；用户显式挑过的语言才是真筛选，与关键词 AND。窗口语义见 `apps/server/AGENTS.md`。
- **界面体检脚本 `scripts/audit-ui.mjs`（改完样式、尤其是改颜色或窄屏尺寸后跑一遍）**：一条命令同时扫三类只有真浏览器才看得见的问题——控制台报错、横向溢出、对比度（含占位符）与命中区。用法 `BASE_URL=http://localhost:PORT [WIDTHS=390,1440] [THEME=dark] [PLAY=320000] node scripts/audit-ui.mjs`，有非白名单问题就以非零码退出。两条踩过的坑写在脚本里：① 站点颜色多出自 `color-mix()`，computed 是 `color(srgb 0.87 0.90 0.95 [ / 0.12 ])`——分量 0~1、斜杠后还有透明度，按 0~255 读或漏掉 alpha 都会把浅底当成近黑，报出一堆假缺陷；② 探针拿「元素自身的背景」算对比度，压在插画（`background-image`）上的字（标题页剧名）会被算成 1:1，那类要照着截图判断，脚本里列了白名单并写明理由。
- **宿主与舞台共用一套深浅主题**：界面走 `html[data-ui-theme="light|dark"]`（`useTheme` 落到 `data-*`，默认跟系统），舞台表面也跟着这个属性取令牌。不要再写 `data-stage-theme`；新写舞台表面时同时确认浅色和深色下的观感。
- **同色不能既当图形又当文字**：状态点的底色要亮（`--success`），同一处的文字要够暗（`--success-ink`）——一枚令牌两用时按主题各配一枚，别拿图形色去写字（`#10b981` 写 11px 的字在纸面上只有 2.42:1）。同类还有 `--badge-ok-ink` / `--badge-warn-ink` / `--placeholder-ink`。**自定义主色必须配墨色**：预设色是成对的（`--accent` + `--accent-ink`），用户自己挑的那个只有一个色，`useTheme.readableInk()` 按亮度在白字与深字里取更清楚的那个（不配就是浅色主色上留白字，实测 1.41:1）。
- - **窄屏（≤720px）是一等场景，不是「缩小的桌面」**。宿主的手机规则集中收在 `app.css` **文件末尾**那一节：级联最后 = 覆盖前面任何基础规则都不必写 `!important`（早期把它放在中间，`stage-top-left-cluster` 一类后文规则反过来把它压掉）。这一节里：剧目库顶栏压成两行（品牌+动作 / 搜索独占一行，`CONSOLE` 让位）、指标栏两列、周目页标题一行 + 主按钮整宽、设置页字段一律上下排、文件页树在上限 32vh、角色/记忆卡两列、立绘三轴两列网格、路线图例从左上角一大块改成贴底一条。**舞台内部（台词条 / 导演栏 / 快捷菜单 / 选肢）的窄屏尺寸归 `packages/stage/src/stage.css` 的同名断点**——宿主只加载那一份样式，写两处只会互相覆盖，而且 dsh-aivn 拿不到 app.css 里那份。手机上舞台顶部分两行（第一行「舞台 ⇄ 工坊」，第二行导演栏整条，仍水平展开不折叠），台词条的正文起在窗顶（与桌面同一个「字起在窗顶」的手感，上留白 40px 让开渐变里全透明的那一段），底缘那一行（状态提示 + 快捷菜单）用 `margin-top: auto` 钉在窗底，快捷菜单从右下角浮层改成底缘那一行的右半（七个入口在 390 宽里排不满就折行）。
- **编辑页的保存动作钉在滚动区底边**：`.save-row`（剧目 / 角色 / 记忆 / Agent 四页）走 `position: sticky; bottom: 0` + `margin-top: auto`（内容不满一屏也贴底）＋ `::before` 铺满左右内边距的底色；下内边距从 `.workshop-tab-pane` 挪到这一行身上（`:has(.save-row)`），否则滚到底时它会比钉住的位置高出一条、回弹一下。**移动端不要再改成 `fixed`**：工坊占满视口时 fixed 贴的是视口底边，而 dock 在内容区底部的待注入队列（对话页）会跟它叠在一起。
- **舞台导演栏在窄屏只留图标**（`.dir-label` 由 `.theater-director .dir-label { display: none }` 收掉，`aria-label` / `title` 里仍写全动作），并且**它与左上角切换器共用同一套黑白表面**（`--stage-chrome-quiet-*`：浅色 `#ffffff` 白底 + `#e2e8f0` 描边 + `#64748b` 字，深色 `#0d1117` 黑底 + `#30363d` 描边 + `#8b949e` 字，不加半透明弱化或蓝灰掺色，确保右上角的黑/白与左上角切换器的黑/白完全统一）：导演栏是压在画面上的器具，重主题色留给台词条、选肢与右下角快捷菜单——只有某一档开着（`.on`）时才在这条上点亮。窄屏下它与左上角「舞台 ⇄ 工坊」同一行、同一高度（两条 chrome 并排，390 宽还剩一百多像素空档）；台词条窄屏最少 30% 高（四五行正文的位置），快捷菜单折行是允许的兜底。
- **焦点环只走 `:focus-visible`，别用带 `!important` 的静置规则把它压掉**：设置页那排输入框曾经同时写了 `outline: none`（焦点态）和 `box-shadow: none !important`（静置态），后者把前者的焦点外晕整条吃掉——键盘走到输入框上一点反馈都没有。给焦点态补 `box-shadow` 时必须同样带 `!important`（静置规则的优先级不允许它被普通声明覆盖）。标题画面那种「选中靠字亮 + 外晕」的菜单也要单独给 `:focus-visible` 补一圈细环，**且环要按输入方式发牌**（`TitleView` 只在 Tab 过之后给菜单挂 `is-keyboard`，选择器 `.atri-menu.is-keyboard .atri-item:focus-visible`）：首屏那枚 `autoFocus` 是「Enter 立刻继续 / 开演」的落点，浏览器却把它一并算进 `:focus-visible`，不设闸的话鼠标用户一进标题页，那列没有底板的纯字上什么也没碰就浮出一圈主题色方块（2026-10-10 用户报的「START 出现绿框」）。
- **窄屏下不许出现「竖排的中文」**——那是某个 flex/grid 项被挤到只剩一个字宽的症状，一律按 bug 处理。三个高发点：页面标题（`.saves-header-title` 一类要 `white-space: nowrap`）、标签-控件两列网格（手机上改单列时**每个控件都要显式 `grid-column: 1`**，漏掉一个 `select` 它会自建第二列、把同行的标签压成竖排）、按钮与只读徽标（`.thread-new`、`.switch-row > span:first-child` 要 `flex: 0 0 auto; white-space: nowrap`）。

  - useWorkshop 状态机（助手一轮的内容是 `WorkshopPart[]`：流式期间在 `state.live`，收束后取 `message.parts`，同一个渲染器读两种来源；`workshop_asset` 带 `toolCallId` 时挂到对应那次调用上，否则留 `message.images`）。
  - **全站关闭键同一套形状**（`app.css` 里 `.stage-panel-close` / `.lightbox-close` / `.picker-close` / `.notice-close` 共用一个基底，舞台包里 `.modal-x` 跟同一套）：**圆、无边框、`currentcolor` 着色、静置 0.66 透明度、悬停浮出一层同色薄底、`:focus-visible` 一圈主题色环**。面板/灯箱这类压在画面上的，底垫一层半透明暗玻璃（`rgb(8 16 30 / 0.34~0.5)` + `backdrop-filter`）。原来是四种不同的方键——回顾抽屉那枚还是实心主题色蓝块，用户点名「有点丑」。
  - **通知条是浮层，不是流里的块**（`.error-banner` / `.warn-banner` / `.ok-banner` 一律 `position: fixed` + `--notice-top`）：以前它们是普通块，一出现就把标题和内容整个顶下去，读起来像页面跳了一下。**顶到标题栏下面**，各屏在根上给 `--notice-top`（剧目库 94 / 设置 69 / 舞台面板 69 / 标题页 76，手机另给一份），工坊例外——它的内容区左边压着 210px 的轨，所以锚在 `.studio-content`（已是 relative）上按内容区居中，也顺带躲开内层滚动区（`overflow` 只在包含块是自己时才会裁掉 abspos 后代）。同一屏可能同时两条（断线 + 失败）时用 `.notice-layer` 叠放；**层内那条的 `position: static` 覆盖必须写在分屏作用域规则之后**（同权重、后写者胜），否则会被再顶一次 56px。素材页顶上那条状态回显同理：徽标一行、判据一行（`.assets-pane-head > .muted { flex-basis: 100% }`）。**结果分类**：回执类（保存成功）5 秒自动收起 + 点击即收；失败类与提示类一律带 `.notice-close` 收起键（32×32 圆钮，右侧；`useDismissible(value)` 管「收起只影响显示」——值一变就重新露出来，不碰产生它的状态）；能重试的给动作而不是只给字——工坊失败条「重发上一条」、音色库加载失败「重试」。**样式取自主题令牌**（`--danger`/`--warn`/`--success` 推左轨、描边、底色与墨色），不是写死的浅色值——早先那三块写的是 `#fbf1ef` 一类固定色，深色宿主主题下会浮出一块奶白。
  - **未保存的改动不许被静默丢掉**（`workshop/dirtyGuard.tsx`）：各页自己知道改没改（草稿与盘上那份比出来），把一个 `dirty` 登记到 context；`requestLeave(action)` 在汇总为真时先弹一个确认框（「不保存，直接走 / 留在这页」），为假就直接执行。**登记处必须挂在 `App` 最外层**：拦人的 handler 有的挂在 `StageScreen` 自己身上（Esc 回舞台），放在 `StageScreen` 内部就读不到；`useDirtyFlag` 是 hook，**必须落在任何早退之前**（CharacterPane 曾在 `if (!roles) return` 之后调它，直接触发 "Rendered more hooks than during the previous render"）。登记键：play / agent / file / memory / characters。
  - **断线与「还没连上」是两回事**：`connected === false` 在初次进页面时也成立，那时底栏写的是「连接中…」，不该摆一条「连接断了」的假警报——所以页面里另记一个 `everConnected`，只有**连过再断**才出横幅、才禁输入（`.warn-banner` + textarea `disabled` + 发送键禁用 + `submit()` 早退）。副作用的另一头：`StageScreen` 的 `onSendDropped` 提示在工坊视图里直接不弹（那边有常驻横幅），否则它会盖在横幅上重复同一句话。
  - **回顾抽屉 = 剧本页**（`BacklogView` 的两段：**剧本** / **原文**）。剧本段铺的是 `buildScriptFeed(lineage.view, transcript, names)` 的结果——**台词与舞台指令按演出顺序合成一条时间线**，不是只有说过的话：换景 / 立绘 / 音效 / 插图 / 舞台效果 / 提前生成 / 停止点各占一行（`.bl-dir`，灰字 + 左竖线，细节走等宽字），停止点把选项一并列出来。**指令文案一律说人话 + 素材名**（「换景 classroom · 音乐 daily」），不出现标签名与 attrs。合成键是事件的 `seq`：台词条目按谱系 nodeId 认领，玩家输入那类没有 nodeId 的按 seq 认领（同一把尺子）；谱系里还没有的新鲜尾巴补在末尾。`feed` 是可选 prop——宿主不传就还是老的单铺台词。**`<ending>` 不进剧本页是设计如此**：它唯一的作用是「到此为止，别再往下写」，没有任何呈现——需要呈现时剧作家用 `<title>` 收尾（用户 2026-10-10 明确）。服务端不落谱系、客户端 `ScriptBuilder` 直接 return 都是这条设计的结果，不是缺口。
  - **有语音的台词挂一枚圆形喇叭徽章**（`.bl-voice`，20px 主题色圆点 + 白喇叭，点了重听）：`voiceAvailable && voiceState(seq) === "ready"` 才出现。**不要给它加字**——试过写成「回听」胶囊（52px 宽），用户否了：一行一句话旁边挂一个词，页面上全是重复的标签。
  - **失败条要能重来**（`.error-banner` 里的「重发上一条」）：服务端已把 `Request aborted` 这类内部串换成人话（`apps/server/src/errors.ts` 的 `userFacingError`），界面上再给一个动作——拿 `state.messages` 里最后一条 user 文本走 `workshop.chat`，人不必自己把那句话翻出来重打。
  - **设置页的保存回执**：保存中是「保存中…」按钮态；成功走 `.ok-banner`（纸面底 + 主题色左边线 + ✓，5 秒自动收起）——它与失败同用橙色警示条会让人以为自己出错了。
  - **助手回复里的 markdown 表格与代码块要有样式**（`.md-body table/th/td/pre/ul/blockquote`）：模型很爱用表格交代「这一轮写了哪些文件」，不给线就是一堆并排的字、列对不上。
  - TurnParts 助手一轮的段落渲染器（按 parts 顺序铺正文气泡 / 「思考」可折叠行 / 工具行；`TOOL_LABEL` 与参数摘要收在这里）。行的展开态默认由「是否流式中、这次调用有没有素材」决定，用户点过之后记进组件本地的 toggled。
  - AssetStrip 素材条（工具行里显示这次调用产出的图，WorkshopPane 与工具行共用。**先图后音频**——一条 flex-wrap 里混排会变成「一张图一个播放器」的锯齿；音频不再是浏览器自带的 `<audio controls>`（一个两百多像素宽的小面板，比整条消息还抢眼），改走 `ui/AudioPill.tsx` 的紧凑胶囊：播放键 + 名字 + 进度条 + 时长，`preload="metadata"` 才拿得到时长。**缩略图一律写 `.asset-strip .asset-thumb`**：这个类名与素材表那排 48×32 的行内缩略图撞过车，后者的规则在后面，会把画廊里的图压成邮票大小）。
  - FileBrowser 剧目文件树/编辑器/预览。
  - AssetsPanel 素材库（**顶上那条状态回显要说清判据**：`readiness.sprites`（`assets/sprites` 任一目录里有图）与 `readiness.background`（`assets/backgrounds` 里有图）两条都真才写「立绘 ✓ 背景图 ✓」，缺谁就写「还缺 …」——原来写的是「素材齐了」，没说是对谁而言、也没说什么时候算不齐；**立绘段在最前**，其后是背景/CG/音效/BGM；角色卡不在这里，归「角色」页：「音色：…」开全屏音色库面板 + 试听，素材行带描述副标题。立绘段一个目录一张 `.sprite-card`——`assets/sprites/<id>/` 里的文件即差分，名牌 / 取景 / 体量 / 锚点四个声明**折在卡里的「声明」一行**（`<details class="sprite-decl">`，摘要写声明过的值、一条没有就写「未声明，按引擎缺省摆位」——折起来也要看得见状态；十张卡常显就是四十行表单），留空＝不声明、落回引擎缺省，写走 `PUT /api/plays/:id/assets/sprite`，逐差分行只给取景覆盖与「重新生成」「删除」，目录级能上传差分 / 出图，段头「生成新立绘」+ 新 id 一行建目录；**标题写引擎真正在用的名字（按 `spriteIdOf` 的绑定反查卡 name → 名牌 → id），名字与 id 不同才把 id 并排带上，没卡就标一句「只有立绘」；目录名与某张卡的 id 同名、而那张卡绑去了别处时补一句「角色 X 的立绘绑的是 Y」，否则用户看到的就是「卡在、图也在，怎么就是绑不上」——不要写「没有同名角色卡」，那是内部诊断，用户刚导进来的角色看到这句只会以为导入失败了**；`focus` 点名的主体排在段首（滚不动：卡片高度随图解码陆续长出来，滚动位置会被顶回去）。**到货刷新走 `subscribeAssetReady`**（助手/舞台那边的导入与后台出图，不是自己发起的也要跟上）。

  - LibraryBrowser 资源库浏览面板（防抖搜索 + 网格卡 + 图片灯箱/音频试听 + 导入/覆盖态 + `target`，素材页与角色/主角卡入口共用一个组件；分类 tab 是背景/插图/**立绘**/音乐/音效，**没有「角色」**——角色卡不是素材，只能从角色页进；角色/主角卡入口传 `only="characters"`，锁死类别且不渲染 tab，两类卡都能导入库里任意角色（主角和别人同权，`assetImport` 只按 target 决定落到 `characters/protagonist.md` 还是 `characters/<id>.md`），立绘包落 `assets/sprites/<id>/` 并把三轴写进 `assets/manifest.json`，不再有 `filter`）。

  - **时间类 CSS 变量必须带单位**：`--fade-ms`/`--move-ms`/`--trans-ms`/`--fx-ms`/`--hover-ms` 一律写 `220ms` 而不是 `220`。漏单位会让**用到它的整条 `transition`/`animation` 简写被浏览器判为无效**（`transitionDuration` 变 `0s`），且不报错——症状是「过渡/动画完全不生效」。`--fade-ms` 曾长期无单位，连带差分交叉淡化、运镜 transform、压暗 filter、退场淡出全部失效（2026-10-07 修）。注意 `app.css` 的 `:root` 覆盖 `stage.css` 的 `.stage-root`（`@import` 在前、`app.css` 自身的 `:root` 在后），两处都要改。
  - **并排的层各自管好自己的 z-index**：`.theater-camera` 下的兄弟层（背景栈 `.theater-stack`、立绘层 `.theater-sprites`、CG 层）彼此的 z-index 是**直接比大小**的。谁要用「内部排序」式的 z-index（栈内新图 2 压旧图 1），谁就得自己 `isolation: isolate` 把那份排序关在层内——不隔离的话那几档数值会跟同一上下文里的兄弟层比，压住本不该压的层。`.theater-sprites` 的 `0` 与 `.theater-stack` 的 `isolate` 是同一条规矩的两个实例（2026-10-08 修：背景栈没隔离，栈内 `z-index:2` 冒泡上来压过立绘层 `0`，换过一次底之后立绘全看不见）。**收口要落在「数值所在的那一层」**——别以为把父层孤立起来就行：camera 自己**已经**因 `will-change: transform` 自成层叠上下文了（实测确认；`z-index:auto` 不等于不是上下文，`will-change` 的 transform/filter、`contain: paint`、`opacity<1` 都会建上下文），但在它身上加 `isolation` **实测无效**——栈内数值与立绘层同在这个上下文里，多套一层并不改变它俩比大小的关系。**诊断这类问题的办法是 `document.elementFromPoint` 在目标元素身上打点看命中的是谁**，再逐层读 `getComputedStyle` 的 `z-index`/`isolation`/`will-change` 找上下文断在哪——立绘被不透明背景完全盖住时，截图上看不出它在不在 DOM 里，只看截图会误判成素材缺失。**纯色场这类「整屏」层不住在背景栈里**：`.theater-fade-veil` 挂在镜头容器下（立绘与 CG 之上），关进栈里就只能盖住背景、人物会浮在黑场里不动。
