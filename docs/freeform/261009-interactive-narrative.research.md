# 互动叙事 / 视觉小说的结构与选择设计：调研笔记

面向用途：为 AI 视觉小说引擎（stage-ai / AIVN）的技能库准备「编剧手艺」素材中与分支、选项、旗标有关的一块。故事结构、人物、台词另见其他三份报告。

---

## 1. 基本词汇与结构类型

来源：VNDev Wiki（https://vndev.wiki/Route）

- **分支（branching）**：玩家输入导致的多条故事路径。输入可以是显式选项、累积决策（好感度），也可以是迷你游戏表现之类的其他方式。分支可以通向多个结局。
- **路线（route）**：一条在视角或内容上与其他分支**显著不同**的故事。
- **共通线（common route）**：所有人都会走过、用来解锁角色线的那一段。通常负责介绍主情节、角色与主题；因为它必须讨好所有人，交互与变化往往比角色线少，长度一般短于角色线。
- **角色线（character route）**：聚焦一个或几个角色，深入其性格、前史、动机与目标，常有该线独有的结局。所有角色线加起来一般比共通线长。
- **无分支** = 线性结构，这类作品被称为 **kinetic novel**（无选项小说）。
- 线性但有会通向 bad end 的岔路 = **gauntlet**（走道）结构。

### 分支的几种拓扑

| 名称 | 形状 | 备注 |
| --- | --- | --- |
| 简单分支 / time cave | 每个选择都开一条新枝，枝与枝不合并 | 不需要追踪变量；**组合爆炸**的坑（4 个二选一 = 16 条，5 个 = 32 条）；只适合短篇 |
| 早期分支（early branching） | 共通线短，早早分出互不重叠的路线 | 每次周目体验差别大 |
| 晚期分支（late branching） | 共通线很长之后才分 | 各线共享同一套背景与事件；玩家重玩时会想跳过共通线 |
| 分叉后合并（split and merge / branch and bottleneck） | 选择开出一条专属支路，几个场景之后**合流**回同一主线 | 交互叙事里最常见的控量手段 |
| 阶梯（ladder） | 不在共通线末尾分叉，而是在**过程中陆续**岔出 | 不同角色/情境在不同的时间点把玩家"从梯子上带下来"；有些选择影响早、有些影响晚 |
| 强制路线顺序（enforced route order） | 真结局/隐藏线需要先通关其他线才解锁 | 常见于有 true route 的作品 |

- 分支的触发方式两大类：**玩家输入后立即生效**，与**用变量追踪**（需要累积多次选择，如好感度，或满足一组前置选择）。
- 流程图（flowchart）既用于开发前规划、估算工作量，也用于游戏内帮玩家追踪已探索的路线。
- 依赖图（dependency graph）用于管理"钥匙—门"式的状态：某条线里玩家可能拿不到另一个场景里的钥匙，需要提前在工具里发现这种死锁。

来源：https://vndev.wiki/Route ；https://visualnoveluniverse.com/en/docs/engine/decision-map

## 2. 共通线的利弊（结构与写作层面的经验总结）

来源：Fuwanovel 论坛长文《The Common Route – An Anatomy of Visual Novels》（https://forums.fuwanovel.moe/blogs/entry/3703-the-common-route-%E2%80%93-an-anatomy-of-visual-novels/）

**强项**

- 承担世界与角色建立的重活，**让各角色线不必再背说明包袱**，主线节奏因此不被拖累。
- 建立一个**可变的现状（malleable status quo）**：各线主题可能彼此矛盾，共通线提供一个足够宽容的底座，让不同走向都像是合理外推；同时也定下全作的基调。
- 控制体量：把世界设定与人物介绍收在一处；被砍掉的其他线的素材可以塞进共通线；玩家反复经过它，可以调节总游戏时长。
- 支持玩家期待（尤其是恋爱题材：没有共通线会让玩家觉得路线选择被剥夺）。

**弱项**

- 容易过载：把太多说明与铺垫堆进去 → 臃肿、节奏慢、留不住人。**共通线不该赖着不走，它是暖场不是主角。**
- 常见变体与选择：
  - 早分支：更快进入路线，适合强调剧情或角色的作品（例：Tsukihime 早早就分成 Near Side / Far Side；Katawa Shoujo 几乎不停留）。
  - 晚分支：所有线有共同背景，但玩家会想跳过。
  - **阶梯结构**：把主情节放在共通线里，角色线只是**可选的扩展**、从章节末岔出；唯一的例外是最终路线直接接在共通线之后作为收束。典型例子 Steins;Gate——它牺牲了非线性的收益，换来更紧凑的叙事，适合惊悚类节奏。
- 作者的建议：不要对共通线过度依恋，先问它是不是这个故事最合适的形状。

## 3. 分支的工程现实（对写作者的约束）

来源：BranchPy《Understanding branching complexity in visual novels》（https://branchpy.com/learn/guides/understanding-vn-branching/）

- 视觉小说剧本本质是**有向图**：标签是节点，跳转是边。一个三选项的菜单就是从同一节点出发的三条边。
- 组合数随选择点**指数增长**（纯二叉不合并）：5 个选择点 = 32 条路径，10 个 = 1024，15 个 = 32768，20 个 = 1048576。
- 大多数 VN 会频繁合流以压低实际路径数，但"在下一章合流"**不等于**这些选择等价：合流之前的那段路上可能有不同的场景、素材与变量状态。
- 因此**不可能测完所有路径**；能做的是静态验证结构（哪些标签存在、哪些可达、哪些跳转指向不存在的目标）。
- 规模经验值：低于约 30 个标签时开发者能维持准确的心理模型；超过 100 个标签时，这个模型几乎总是不完整或有错的。
- 图上能一眼看出的三类问题：**回不来的分支**（每条选择都开一条永不汇合的路，工作量逐章翻倍）、**孤儿节点**（没有任何连接能到达，多是旧版本的遗留）、**假分支**（两条路走到同一个地方，中途什么都没变——不是错，但它应该是一个有意的决定而不是疏忽）。

来源：https://branchpy.com/learn/guides/understanding-vn-branching/

## 4. 选择的设计：有意义 vs 伪选择

- 决策图工具把"假分支"列为需要检查的结构问题（见上）。这给出了一个实用的判据：**从选择到合流之间，有没有东西真的变了**（场景、信息、关系、变量状态）。没有变，这个选择就是装饰。
- 好感度/变量追踪的机制现实：玩家往往要累积多次选择才能触发分支；反过来，这允许作者把单个选择做得不那么致命，同时仍然让累积有意义。
- 「引用式」的设计手法（来自 AIVN 引擎自身的能力，非外部文献）：如果剧本里引用了剧目没有的素材 id，宿主会自动去素材库导入同名条目；没有就静默降级。对写作者的含义是——不必为了"缺一张图"改写剧本。
