# 视觉通道故障：截图验收会静默退化成「没看过图」

日期：2026-10-06 ｜ 记录人：主工程师

## 发生了什么

停止点改动的实机验收里，三张实拍截图入库供复核。本轮复核方（full-auto 下的 `auto-human` 代理）
报告**它的视觉通道故障**——图看不到。它没有停在这里，而是改用截图里那块**机器可读的 DOM 读数
水印**（`aria-label` / `aria-disabled` / `disabled`）加 e2e 证据链完成了收口。

同一时段主工程师这一侧的 `modlens` 读图是好的：三张图都拿到了逐字转述。所以这次故障在**复核方
那一侧**，不在图本身（此判断只覆盖同一时段，未做进一步定位）。

## 为什么值得单独立一条

它挡的不只是这一次看图：任何「截图验收」都会撞上，而且**症状会伪装成「agent 说它没看过图」**
——听起来像 agent 偷懒或撒谎，实际是通道坏了。更糟的是它可以**静默**：复核方照样给出「通过」，
而它其实一个字都没看见。

## 对策

1. 验收证据尽量**机器可读**：程序化读数、DOM 快照、会话日志原文，都比一张图更耐通道故障。
   这次能收口靠的就是截图里那块读数水印。
2. 需要肉眼判断的（观感、布局、审美）**先确认通道是通的**再开始，别在通道坏掉时把「采信证据链」
   当成「看过图」。
3. 复核方看不到图时应当**明说通道故障**并按第 1 条降级，不要含糊地给结论。
