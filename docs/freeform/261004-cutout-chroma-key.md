# 立绘抠底改成纯色键（色键底）

日期：2026-10-04 ｜ 相关代码：`apps/server/src/cutout.ts`、`playAssets.ts`、`agentkit/recutTool.ts`

## 为什么换

旧管线是「白底 + 一套猜白底的启发式」：滞回阈值（strong/weak）决定谁是底色种子、漫延到哪，
连通域筛内外决定哪块白算背景，`minHole` 决定内部小块留不留。它的问题是结构性的——
白衣服白袜子和纯白底**本来就是同一种颜色**，算法只能靠形状猜，猜不准就是灾难
（用户原话：「碰到白衣服白袜子的太灾难啦」）。实测绿底原片腿间残留 1477px、
上臂根 3597px，都是这套猜法的漏网。

新分工：**底色由出图那一步负责选对**——立绘后缀要求一个「不与角色配色重复的单一纯色底」
（默认纯绿 `#00FF00`，角色本身是绿色系就换纯品红/纯蓝）。底色一旦不撞色，抠底就只剩颜色一件事，
不需要再猜形状。

## 新算法

1. 底色 = 整圈边框的逐通道中位数（均值会被角落水印拽偏）。
2. **全局色键**：离底色不超过 `tolerance` 的像素一律算背景——不分内外、不看连通性、没有面积阈值。
3. 掩膜边界**两侧**各 `edgeBand` 像素内，用闭式解 `a=(B−I)/(B−F)` 反解真实覆盖率并 unblend；
   纯底色解出 0、半覆盖解出中间值。
4. 裁外框 → 等比缩放 → 底部居中落 9:16 画布。

删掉的东西：strong/weak 滞回、`components`/`touchesEdge`、`minHole`、`interior`、
`keepLargestForeground`、`envBool`。旋钮从六个降到三个：
`STAGE_CUTOUT_TOLERANCE`(48) / `STAGE_CUTOUT_KEY_SMOOTH`(0.8) / `STAGE_CUTOUT_EDGE_BAND`(4)。

## 量过的证据

`suzune/neutral`（绿底原片 768x1376 → 1080x1920）：

| 指标 | 旧产物 | 新（tolerance 48） |
| --- | --- | --- |
| 实心残留（alpha=255 且离底色 ≤40） | 328 px | **0** |
| 可见绿毛边（偏底色且 alpha≥128） | 1369 px | **165** |
| 不透明像素总数 | 785,130 | 810,110（多出来的都是被旧管线啃掉的抗锯齿边缘） |

- 容差扫：32 → 22px 实心残留（无降噪）；40 → 0；48 起可见毛边进入百像素量级，56/64/80 收益递减
  而人物像素同步递减，**取 48**。带宽 6 能把绿毛边再压到 150，代价是把 1.7 万实心像素啃成半透明、
  多出 1.1 万 alpha 1~7 的幽灵像素，**默认仍取 4**。
- 碎屑：新输出有 698 个与主体不连通的不透明小块，但**没有一个块含 alpha≥200 的像素**
  （旧输出同样有 440 个），是半透明幽灵边，肉眼不可见，因此**不加碎屑过滤**。
- 剩下的 443px 绿毛边是 1~3px 宽的边缘碎条（最大一条 38px），来自源图 JPEG 环纹：掩膜边界往外那几列
  本身就是「底色 + 一点前景」的混合，覆盖率解出来是中间值，颜色也就还偏绿。要更干净只有提高出图分辨率
  或换成宽带宽（见上，得不偿失）。

## 顺手修掉的两个原实现数学错误

这两个公式是从白底那版照搬过来的，只在「底色的每个通道都比前景亮」时成立——白底恰好满足，
换成绿底（红、蓝两路都是 0，比肤色暗得多）就立刻暴露：

- `solveAlpha` 的覆盖率分母不能取 `|B−F|`：分母一取绝对值，符号就翻了，解出负数被 clamp 成 0，
  会把带色的轮廓整圈啃掉。必须用带符号的 `B−F`。
- `unblend` 少乘了一个 `1/a`：正确解是 `F = I + k·(I − B)`（k=(1−a)/a），原来写的 `I − k·B`
  在白底上看着差不多，换绿底就是一层压不掉的绿边。

## 已知边界（都是设计取舍，不是 bug）

- 与底色撞色的角色内容会被照抠不误——这正是「底色必须选对」的原因，修法只有换底色或调 `tolerance`。
- 白底旧图走新管线会啃白衣与浅肤色：白底那套逻辑已按用户要求整体删除，不再维护第二条路。
- 轮廓残留的绿毛边来自源图 JPEG 环纹（165px ≈ 0.02%），要更干净只能提高出图分辨率。
