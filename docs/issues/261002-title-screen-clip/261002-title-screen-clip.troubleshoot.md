# 标题画面剧目名被切 排查

**状态：已修复（2026-10-02，改 `apps/web/src/app.css` 的 `.title-body`）。**

## 现象

手机上打开剧目标题画面（`/#/play/mh`），剧目名顶部被切掉一截。视口越矮切得越多：360×640 只剩标题第二行的一半，360×560 整行标题都在屏幕外。桌面不出现。

## 根因

`.title-screen` 挂在 `.screen` 上：`height: 100%` + `overflow: hidden`。里面的 `.title-body` 是 `flex: 1 1 auto; min-height: 0` 的栅格，窄屏（≤900px）走 `align-content: center`、宽屏走 `align-items: center`——两处都是把内容在剩余高度里居中。

标题画面的内容（标题 + 故事前提 + 就绪提示 + 六个菜单项）比手机视口高。居中遇到放不下会同时向上和向下溢出，向上的那截被 `.screen` 的 `overflow: hidden` 吃掉，吃掉多少取决于视口还剩多少高度——所以看起来就是「标题被截断」，而且越矮的手机越严重。

标题本身没有任何截断样式：`.title-name` 没有 line-clamp，实测横向溢出在 320/360/390/412px 四种宽度下恒为 0。

## 修复

`.title-body` 两处居中改成 `safe center`，并给这一层加 `overflow-y: auto`：

- `safe`：内容放不下时对齐退化成 `start`，只往下溢，不往上切；
- `overflow-y: auto`：往下溢出的部分滚得到。

滚动容器放在 body 这一层而不是 `.title-screen`，是为了让绝对定位铺满的底图 `.title-art` 继续钉在屏幕上不跟着滚。

## 验证

Playwright 实测 `.title-name` 的视口内位置（`nameTop < 0` 即被切）：

| 视口 | 修复前 nameTop | 修复后 nameTop |
| --- | --- | --- |
| 412×839 | 47 | 47 |
| 390×780 | 7 | 16 |
| 360×740 | −13 | 15 |
| 360×640 | −63 | 13 |
| 360×560 | −103 | 11 |
| 780×360（横屏） | — | 7 |
| 1280×800（桌面） | 191 | 191 |

公网站点（自建命名隧道，见 `named-cf-tunnel` 技能）复测一致。360×640 滚到底，六个菜单项与页脚都在。桌面 1280×800 内容不高，`.title-body` 不出现滚动条（`scrollHeight === clientHeight`），版面与修复前一致。

## 备注

舞台侧栏头部的剧目名 `.side-title` 另有一处省略号截断（桌面 232px 栏宽下溢出 85px，手机抽屉 52px），与本问题不是同一处。那块正在被另一条改动重构，本轮没动。
