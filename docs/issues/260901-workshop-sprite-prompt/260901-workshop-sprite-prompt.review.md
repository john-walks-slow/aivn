# 检视：这次改动的取舍

## 引擎侧

**后缀改成只说构图** —— 一句话里去掉的是「twin tails」，加的是「hair and the arms」。留白要求不变（抠底仍要能分开剪影），
不发明人物特征。风险是长发的发梢会贴到手臂上、留白不如以前干净；真机这轮的图边缘没出现啃掉。

**出图记录落 `assets/generated.json`** —— 被否掉的两个方案：
- 写进 `assets/manifest.json`：实跑证明会被工坊的 `edit_file` 整条替换掉（两个写者），顺带把手写表格的空行分组冲掉。
- 写进 `media-cache/img/manifest.json`（引擎独占的老台账）：不会被冲掉，但那个文件不进 git，换机器 clone 就没有记录；
  而且立绘的记录在那里对工坊不可见（media-cache 不在 PlayFiles 白名单里），等于留了个谁也读不到的档。

选新文件的理由是「一张表一个写者」：描述是人话、归人写；prompt 是原样留档、归引擎写。
代价是多了一张表、且 CG 页要多读一个文件（复用既有的「静态素材 + 同 id 生成记录」那条路径，页面零改动）。

**并发记账走剧目锁** —— 并发出 6 个差分时六个读改写会互相冲掉，`withPlayConfigLock(store.dir)` 与 play.json 补写共用一把锁。
测试钉了 7 条记录（6 个差分 + 自动补的定妆照）一条不少。

**记账失败只 warn 不抛** —— 图已经落盘了，为一条记账把一次成功的出图报成失败更糟；消息里带 id 与原因，图和 prompt 对不上时查得到。

## 提示词侧

四条规则（外貌锚点 / neutral≠normal / 逐条核对 / 失败原文）都是把实跑里模型做错的事直接写成禁令，不写推理过程——
system prompt 每轮都进上下文，展开的画风与构图知识留在 skill 与剧目记忆里。

描述表的键约定没有只靠提示词：工坊仍然写了裸键 `neutral`（同一张表里既有裸键又有规范键是既有现实），
所以服务端 `prompt.ts` 与素材页 `AssetsPanel` 改成按字段合并。这是提示词层修不住的：改提示词只能降低概率，改读取才是真的修好。

## UI

只改了 `AssetsPanel` 的描述查找（多一次回落），没有新增元素、没有改样式。

## 已知遗留

- 立绘差分 prompt 的记录只有文件与工坊能读，UI 上没有展示位（CG 页有，因为 CG 页本来就摊 prompt）。等需要时再加。
- `assets/generated.json` 会随每次出图重写一次（`JSON.stringify(..., 2)`），文件变大后 diff 会变大；条目是按 id 覆盖的，不会无限增长。
- demo 的 `assets/manifest.json` 里差分描述全是裸键（历史写法），没顺手迁移成 `<角色id>/<差分名>`：合并后两种都能查到，迁移属于另一件事。
## 追加检视（2026-10-01 晚，两轮追加实验）

### 模型下拉选不动（真机撞出来的）

为了验证「工坊用视觉模型自查」，把工坊模型改成 `gemini-3-flash`，下一轮直接报
`Provider cpa has no API implementation for "google-generative-ai"`。
`resolveCpaModel` 克隆内置目录的模型元数据时把 `api` 一起继承了，而 cpa 网关只有 OpenAI 兼容面——
模型下拉的数据源是网关清单（与内置目录无关），所以列表里天然会有 api 不是 OpenAI 的 id，选中即坏。
两处构造点显式钉 `api: "openai-completions"`，单测钉死。

### 立绘的抠底边缘是批间波动，不是回归

三张立绘的半透明边缘像素占比：双马尾那张 1.1%、第二张 3.8%、第三张（视觉自查那张）1.0%。
色键抠底对浅色主体天然有代价：白衬衫、白裙、发梢与纯白底的色阶太近，键值一刀下去连人带背景一起啃。
3.8% 那批在舞台上表现为白色衣袖半透明（能透出背景），读图模型会报成「抠图伪影」。
这一条没有代码改动，是抠底策略的固有边界；要不要收（去白边 / alpha 收紧 / 提示词里要求更硬的纯白底）另议。

### CG 目前拿不到垫图（设计缺口）

`referencesFor()` 只给立绘差分返回 neutral 参考图，CG 与背景一律 `[]`，
所以「参考人设出 CG」今天在引擎里做不到——`generate_image(kind="cg")` 没有参考图入参。
直接打网关做了对照（同一条 prompt，16:9 2k）：

| | 发色/瞳色/泪痣 | 服装 | 发饰与发型 | 模型自作主张的部分 |
| --- | --- | --- | --- | --- |
| 纯文本锚点 | 全对上 | 领巾/白裙/相机对上 | 白缎带对上 | **多了一件藏青开衫** |
| 垫立绘作参考 | 全对上 | 同样对上，且没加开衫 | **换成黑蝴蝶结、多了刘海小辫** | 场景从屋顶栏杆改成铁丝网 |

结论：文字锚点给的是「同一类人」，垫图给的是「同一个人」；但垫图也不能锁死发型细节——
构图一变模型就会重新设计发饰。两条一起上（垫图锁脸与服装，文本补锚点与景别）才稳，
且 prompt 要指定景别，否则袜子和鞋这类关键细节直接出框（两次实验都是 medium shot 裁到大腿）。
