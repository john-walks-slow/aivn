# 音色库搜索：搜不到榜外音色 / 界面上的标签区域

触发来源：外部转述「它的音色库只在全局热门 1000 条里**本地过滤**，雷姆这种榜外音色搜不到；
我们让搜索框直接走 Fish 全库标题搜索；连那个 list_voices 都支持 tag 和常用 tag 了」。

## 先纠正机制：没有本地过滤

搜索框从来不是本地过滤——它一直把关键词发给服务端，服务端再拼到 Fish 的 `title=` 上（全库子串搜索）。
浏览器里抓到的请求就是证据：

```
[req] /api/voices?language=en&q=%E9%9B%B7%E5%A7%86      ← 有关键词，走服务端
[req] /api/voices?q=%E9%9B%B7%E5%A7%86                  ← 摘掉语言后 13 条
```

`/api/voices?q=雷姆` 在线上实例上实测 **13 条 / 1.1s**，与「他们」量到的 13 条是同一批数据。

## 但「雷姆搜不到」能复现——根因是默认语言筛

面板把语言下拉**预选成浏览器系统语言**，而关键词是跟它 AND 的：

| 浏览器语言 | 实际请求 | 结果（2026-10-10 实测） |
| --- | --- | --- |
| en（本机 VNC / headless 浏览器就是 en-US） | `?language=en&q=雷姆` | **0 条** |
| zh | `?language=zh&q=雷姆` | 2 条 |
| ja | `?language=ja&q=雷姆` | 10 条（日语那几条） |
| 全部语言 | `?q=雷姆` | **13 条** |

（条数随公共库上下架漂，但顺序稳定：只有「全部语言」才是全库那 13 条。）

英文系统的用户输「雷姆」拿到 `0 条 / 没有匹配的音色`——他看到的是「搜不到」，而不是
「语言没选对」。**把「浏览起点」当成了「筛选条件」**，全库标题搜索的意义正好被它吃掉。
见 `01-before-en-language-0.png`。

## 界面上那排标签：先修好，再去掉

chips 原来是从**当前窗口现数**出来的高频标签：窗口只有几十条（或像上面那样空）时 chips 跟着空
——实测 en 窗口下 **0 个标签**，界面上一个都看不到，而 `list_voices` 描述里那份常用词表
（画风 / 性别年龄 / 语气 / 质感 / 用途）只喂给了模型。

第一轮把它固定成那份词表（`@aivn/core` 的 `VOICE_TAG_GROUPS`，与描述**同一份**，顺手补上
原本漏掉的 `anime` / `character-voice`）。实拍后发现它在手机宽度上要占五六行，
**用户裁决：标签区域占地方，去掉**。最终形态：

- 面板只剩「搜索框 + 语言下拉 + 卡片网格」，标签筛选从界面上撤掉；
- 标签能力本身照旧：`GET /api/voices?tag=`（≤4 个、并集）与 `list_voices` 的 `tags` 都在，
  词表留在 core 里给工具描述用。

## 修法（最终）

1. **语言下拉分两种身份**（`useVoiceCatalog.ts` 的 `effectiveVoiceLanguage`，唯一入口）：
   - 系统语言默认 = 浏览起点，**一有关键词就摘掉**，搜索始终是全库标题搜索；
   - 用户**显式挑过**的语言才是真筛选，与关键词 AND（要「日语里的雷姆」仍只出那 10 条）。
2. **撤掉面板的标签区域**：chips、面板侧的 tag 状态与查询参数（`VoiceFilter.tags` /
   `api.voiceCatalog` 的 `tags`）一并清掉，不留半截死代码；`.picker-tags` 样式随之删除
   （`.chip-btn` 仍归立绘差分多选用）。面板之外的一律未动。

## 回归面

- 无关键词的浏览行为不变：仍按系统语言预选窗口（中文系统看中文音色）。
- 显式挑过语言的搜索 = 语言与关键词 AND；清空关键词回到该语言的浏览窗口。
- 服务端查询面、标签筛选、工具 `list_voices`（tags / gender / 分页）全未改动。
