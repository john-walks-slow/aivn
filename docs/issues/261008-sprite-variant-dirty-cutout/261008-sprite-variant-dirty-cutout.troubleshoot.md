# 立绘差分被抠成镂空（角色身上透出舞台背景）

## 现象

testtest 剧目舞台上，**差分**（smile / surprised / serious / thinking / worried）到处是
镂空与半透明的破洞：脸上、制服上、大腿上大块透出舞台背景，只剩轮廓与深色部件还在；
同一角色的 `neutral` 定妆照却是干净的。

用户原话：「角色（例如莉莉丝）的立绘差分都抠坏了」，并怀疑「是不是某些操作重复抠图了」。

## 复现与量化

不依赖实机，直接量盘上的成品。指标：**内部空洞率** = 从画布四边做透明区洪泛，
淹不到（= 被前景包住）的透明像素 ÷ 前景像素。这叫「该实心的地方被抠穿了」，
与角色轮廓本身的凹陷（腿间、腋下）无关。

「出图时的底色」不能靠猜——盘上有**两个**留底原片根目录
（`plays/<id>/media-cache/sprite-sources/` 与 `media-cache/sprite-sources/<id>/`），
不同剧目的成品出自不同根。所以对每张成品**逐一试**：拿每个候选源图重跑一遍抠底，
看哪一份能**复现**盘上这张（alpha 差异 < 0.2%）。用复现出来的那一份定底色：

| 能复现成品的源图底色 | 张数 | 平均内部空洞率 | 中位数 |
| --- | --- | --- | --- |
| 品红（MAGENTA） | 5 | 1.69% | 0.49% |
| **绿幕（GREEN，设计值）** | 62 | 1.85% | 0.66% |
| **白底（WHITE）** | 30 | **20.55%** | 13.74% |
| 灰底（GRAY） | 3 | 16.18% | 10.96% |

色键底（绿/品红）合计 67 张，平均 1.8%；白/灰底合计 33 张，平均 20.1%。
testtest 逐张（全部由 per-play 根复现）：

```
sayo/surprised     WHITE    55.51%     kanon/serious      WHITE    27.37%
lilia/surprised    WHITE    36.02%     protagonist/smile  WHITE     6.49%
kanon/smile        WHITE    27.60%     rin/thinking       WHITE     5.09%
lilia/smile        GRAY     26.63%     protagonist/worried WHITE    6.23%
lilia/neutral      GREEN     3.79%     rin/neutral        MAGENTA   0.16%
kanon/neutral      MAGENTA   0.88%     sayo/neutral       GREEN     0.13%
```

规律一句话：**所有 `neutral` 都是色键底（干净），所有差分都是白底/灰底（烂）**。

对照图（上排 = 模型返回的原图，下排 = 入库成品压在品红上）：
`docs/issues/261008-sprite-variant-dirty-cutout/2608-sprite-variant-dirty-cutout.evidence.png`

## 根因

不是重复抠图。两次抠同一张图只会多啃 ~1% 的 alpha 边缘（实测：对已抠好的透明 PNG
再跑一遍 `cutout()`，alpha 差异 1.06%，视觉上模型线稿本身受不住第二遍 —— 但绝无可能
造出 24%~55% 的内部空洞）。真正的原因是**抠底算法与出图实际给的底不匹配**：

### 1. 引擎只按「出图时有没有留底原片」这一条路走，差分走的是白底

`PlayAssets.produce()` 把模型返回的原图**抠一次**、落草稿；`commit()` 把它搬进
`assets/`、把抠底前的原片搬进 `media-cache/sprite-sources/`。差分没有第二次抠。

但**模型返回的底并不是绿幕**。实测 testtest 全部差分的源图底色：

```
lilia/surprised.jpg    253,253,255  (白)
lilia/smile.jpg        197,197,197  (灰)
kanon/smile.jpg        250,250,250  (白)
sayo/surprised.jpg     253,251,252  (白)
protagonist/smile.jpg  253,251,252  (白)
rin/thinking.jpg       253,251,252  (白)
```

而 `lilia/neutral.jpg` 是 `1,250,10`（纯绿）、`protagonist/neutral.jpg` 是 `254,75,252`（品红）——
即定妆照老实按提示词铺了色键底，差分没有。

### 2. 白底对纯色键是「最坏底色」，会把角色打穿

差分提示词的底色约束是 `IDENTITY_TAIL`：

> `same single flat solid background colour as the reference image`

它只说「跟参考图同色」，**没有再点名绿幕**——而差分的参考图是**已经抠过底的
`neutral.png`（一张透明 PNG）**。透明像素没有颜色；模型拿到这种垫图后，
在自身上下文里把它还原成白/灰，于是差分出来是白底。

`cutout.ts` 是**全局纯色键**（不看连通性、不分内外：腋下、腿间的真空隙也是底色，
所以必须全局）。底色一旦是白色，算法就把角色身上**一切离白不超过 `tolerance=48` 的像素**
判成背景：

- 白袜 → 直接抠穿；
- 白制服、粉白外套、白领 → 大面积半透明；
- 银白发（`lilia` / `sayo`）→ 发丝整片消失，这就是用户看到的「抠坏了」；
- 黑发角色（`protagonist` / `rin`）→ 只烂白袜与浅色衣物，所以空洞率低得多（6% vs 55%）。

注意这不是「锯齿/毛边」级别的瑕疵，而是**主体被判定为背景**——`neutral` 在绿幕上
判成背景的只有 0.13~3.79%。

### 3. 为什么 `neutral` 干净、差分烂

| | 参考图 | 提示词底色约束 | 实际底色 | 结果 |
| --- | --- | --- | --- | --- |
| `neutral` | 无（或用户给的既有图） | `COMMON_TAIL` → 点名绿幕 `#00FF00` | 绿/品红 | 干净 |
| 差分 | **已抠底的 `neutral.png`** | `IDENTITY_TAIL` → 只说「跟参考图同色」 | 白/灰 | 打穿 |

绿幕那套是 `a7809fe3`（2026-10-04 17:02）落地的：`COMMON_TAIL` 当时换成了
`KEY_BACKGROUND`（点名纯绿 / 绿系角色用品红）。但 `IDENTITY_TAIL` 是**在 `COMMON_TAIL`
之前单独拼**的（`identitySuffix()` 只拼 `IDENTITY_TAIL`，不含 `KEY_BACKGROUND`），
于是差分这条分支漏掉了绿幕要求——只改了一半。此后所有白底差分全部被打穿，
testtest（10-07）、320000（10-07）都在其中。

### 4. 量化验证

把绿幕源图按正确路径抠一次，再模拟「模型把抠好的透明图还原到白底、引擎按白底抠」：

| 角色 | 绿幕抠底（正确） | 白底抠底（模拟） | 盘上成品 |
| --- | --- | --- | --- |
| sayo | 11.06% | 67.66% | 11.06% |
| lilia | 28.65% | 54.50% | 28.65% |
| kanon | 1.29% | 28.26% | 1.29% |
| protagonist | 0.89% | 7.56% | 0.89% |

「绿幕抠底」一列与盘上成品**逐像素相等**（alpha 差异 0.00%，14/14 张全中）——
成品就是「源图过一遍 `cutout()`」的结果，没有第二次抠；
「白底抠底」一列正是白底差分的量级。机制闭环。

## 与用户猜测的关系

「是不是某些操作重复抠图了？」——**不是**。逐张比对成品 alpha 与「能复现它的那份源图
重跑一遍抠底」的结果，全部吻合到 0.2% 以内；且重复抠图的量级（对已抠好的透明 PNG
再抠一遍，alpha 差异 1.06%）与观察到的成片镂空（24%~55%）差两个数量级。

真凶是**差分的出图底色跑成了白色/灰色** + 纯色键算法对白底必然打穿。

## 坏味道：约束被复制了，然后只改了一份

这个 bug 的实现层根因是一处典型的坏味道——**同一条不变量在多处各写一遍**。

「立绘底必须是单一色键色」这条不变量，在 `playAssets.ts` 里被表达了两遍：

| 分支 | 走哪个常量 | 提不提绿幕 |
| --- | --- | --- |
| `neutral` | `humanSuffix` → `COMMON_TAIL` → **`KEY_BACKGROUND`** | 提（纯绿 / 绿系用品红） |
| 差分 | `identitySuffix` → `IDENTITY_TAIL` | **不提**，只说「跟参考图同色」 |

`COMMON_TAIL` 已经通过 `KEY_BACKGROUND` 承载了这条不变量；`IDENTITY_TAIL` 是第二份
手写副本，10-04 绿幕改造时只改了 `COMMON_TAIL` 那一份，差分这份被漏掉，于是差分白底、
被抠穿。**重复本身不是问题，重复 + 只改一份才是。**

它还顺带长出了两个同源毛病：

1. **两处真的重复了一句一模一样的话**：`KEY_BACKGROUND` 尾句
   `No gradient, no shadow, no texture, no decoration, no text.` 与 `IDENTITY_TAIL` 尾句
   `no text, no shadow, no gradient.` 是同一句的两个版本（还只对上了三个词）。
2. **拼接靠手写标点**：`humanSuffix` 用 `+` 拼，调用方 `suffixFor` 又补 `.`，
   于是出了 `one arm.. Same character as the reference image` 这种双句点——
   实测 57 条差分 prompt 里有 **30 条**带着 `..`。
   这是「碎片 + 手拼分隔符」的必然产物，不是模型写出来的。

正确形状：**把「底色」当成一个独立维度，不分 `neutral` / 差分，两条分支走同一个出口**。
`KEY_BACKGROUND` 已经是这段文案的唯一真相源了，差分支应该复用它而不是另写一句；
同理画风与「不加字、不加影、不加渐变」也各只有一份。重构后 `IDENTITY_TAIL`
只剩它真正独有的那句「跟参考图保持同一身份」，其余全部由共享出口补齐。

## 修复路径

四处一起改：

1. **差分的提示词出口复用 `KEY_BACKGROUND`**（根因修复）：把 `IDENTITY_TAIL` 里那句
   `same single flat solid background colour as the reference image` 换成与
   `COMMON_TAIL` 同一份色键要求。这是唯一能治本的一条：只要差分还是白底，
   无论怎么调 `tolerance` 都会打穿。
   顺带把碎片拼接改成「片段数组 + 统一 join」的共享出口，消灭 `..`。
2. **差分垫图优先用带色键底的原片**（次因）：`referencesFor()` 现在恒垫
   `assets/sprites/<id>/neutral.png`——一张**已经抠过底的透明 PNG**。留底目录里那张
   `neutral.jpg` 才带得动「同底色」这条指令，也顺带让「同一个人」的参考更准。
   注意**不能无条件换**：`assetImport.ts` 导入的（用户自己给的）立绘直接落
   `assets/sprites/`，**不写留底原片**——这种角色只有抠好的 PNG 可垫。
   所以是「有原片就用原片，没有就退回现在的 PNG」，不是替换。
3. **入库前做底色体检**（防回归）：现在这种图会一路静默入库，只有用户肉眼看得出来。
   抽一次整圈边框色，非色键底（绿/品红）就报警或直接判失败。
   这也是唯一能兜住「垫图只得是透明 PNG」那类角色的手段。
4. **补测试**：现有 `playAssets.test.ts` 只对 `neutral` 断言了色键底
   （`single flat solid colour used as a chroma key`），差分那条只断言了景别与
   「只改表情」——**恰恰漏掉了出问题的这一条**。差分用例必须同样断言色键底。

已经烂掉的成品**不必重画**：留底原片还在（见上文两个根目录），按新的提示词重出差分即可；
若只是想救图，`recut_sprite` 对白底源图无能为力（它仍是纯色键，白底照样打穿）。

## 置信度

95%。机制由三条互相独立的路印证：
「底色分类 × 内部空洞率」的统计相关（n=100，色键底 67 张平均 1.8% vs 白灰底 33 张平均 20.1%）、
「能复现成品的源图就是吃进去的那张」的逐张复现（107/145 张唯一复现，
其余 38 张是 `random` / `320000` 里没有留底原片的老图，空洞率普遍很低）、
以及提示词代码路径（`identitySuffix` 不走 `KEY_BACKGROUND`）。

唯一没做实的是差分白底的确切成因（模型如何解读透明垫图），
但这不影响修复方向——只要差分明确要求色键底、且垫图换成带色键底的原片，问题即消失。

## 验收标准

- 出的新差分源图整圈边框色为纯绿 `#00FF00`（绿系角色为品红 `#FF00FF`）。
- 新差分成品的内部空洞率 ≤ 对应 `neutral` 的水平（当前色键底批中位数 0.66%）。
- 回归用例：差分提示词同样断言含色键底要求（与 `neutral` 同一份文案）。
- 回归用例：喂一张白底 + 银发角色的源图，抠底结果应报错或至少不静默产出打穿图。
- 实机：testtest 重出全部差分后，舞台上看不到角色身上透出背景。
