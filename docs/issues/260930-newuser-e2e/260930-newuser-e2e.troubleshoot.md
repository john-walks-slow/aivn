## P1　工坊对话页出现两个都叫「新会话」的按钮

**现象**：空会话状态下，线程切换器（`.thread-toggle`）和它右边的按钮都显示「新会话」，并排两个同名控件，用户无法分辨哪个是「当前会话」哪个是「新建」。

**位置**：`apps/web/src/workshop/WorkshopPane.tsx`

```
const threadName = workshop.freshThread ? "新会话" : (activeThread?.title ?? "新会话");
```

`state.threads.length === 0` 时根本没有可切换的线程，切换器本就不该出现；「未落名」的会话也不该和新建按钮同词。

**修法**：`threads.length === 0` 时不渲染切换器；未落名会话的切换器文案改成「未命名会话」。

## P2　自动播放开关没有状态语义

**现象**：`.dir-btn` 上的 title 恒为「自动播放」，点开只换图标和 `.on` 类，没有 `aria-pressed`。读屏用户听到的是「按钮 自动播放」，不知道当前是开是关；hover 提示在开启后反而变成陈述句歧义。

**位置**：`apps/web/src/stage/StageTheater.tsx`

**修法**：`aria-pressed={on}`，title 改成「自动播放：开 / 关」。

## P3　侧栏折叠时的提示词和展开后的菜单名不是一回事

**现象**：折叠态 hover 提示是「正在演的内容 / 这一场说过的话 / 岔出去的世界线 / 改设定与剧目文件」，展开后菜单名却是「舞台 / 回顾 / 路线 / 工坊」。同一个东西两套名字，用户要在心里做一次映射。

**位置**：`apps/web/src/stage/StageShell.tsx` 的 `{ id, label, icon, hint }`。

**修法**：hint 首词与 label 对齐（`舞台：正在演的内容` 这样），保证折叠/展开是同一个词根。

## P4　侧栏分区标题「看什么」语义不明

**现象**：「看什么」这四个字同时挂在舞台/回顾/路线/工坊四个视图上方，但舞台是「演」，不是「看」。

**位置**：`apps/web/src/views/StageScreen.tsx`

**修法**：改成中性分区名（「这个剧目」或直接去掉），让四个视图自己说话。

## P5　工坊 agent 会给出无法执行的指引

**现象**：agent 回复「请前往舞台的「路线」视图，在当前节点后面继续输入你的表态或推进剧情」。但路线视图里每张卡只有「回到这里 / 由此分岔」两个按钮，**没有任何输入框**。用户照做会直接卡住。

**修法**：改 agent 的系统提示，让它只引用真实存在的入口（舞台选肢里的「自由发挥…」、导演栏「插一句」、停止点卡片），或者在 agent 提示里明确「路线视图不能输入」。

## P6　未就绪剧目的主按钮排在解释上面

**现象**：标题页把灰色但形状/位置都很像主 CTA 的「开始新周目」放在**上方**，「还不能开演：缺 故事前提…」放在**下方**。逻辑是对的（按钮 `disabled` + `title="缺：故事前提"`），但视觉层级的先后和阅读顺序相反，新用户第一眼落在不能按的按钮上。

**修法**：就绪说明上移到按钮之前。

## P7　生图失败时把后端原始 JSON 弹给玩家

**现象**（截图 `40-stuck.png`）：

```
生图失败：生图 HTTP 400: {"error":{"message":"unknown provider for model gpt-image-2",
"type":"invalid_request_error","code":"model_not_found","param":"model"}}
```

模型名、provider、错误码、参数名全暴露在玩家界面上，而玩家能做的只有「等/去设置里换出图后端」。这既是无用的噪音，也违反「玩家界面不出现引擎内部说法」。

**位置**：`apps/web/src/stage/generatedAssets.ts` / 触发 toast 的地方。

**修法**：toast 只说人话（「背景图生成失败，已用氛围底色顶上，可在剧目库「设置」里换出图后端」），原始错误降到 console。

## P8　默认模式下，停止点没有任何「说点什么 / 分岔」的出口

**现象**（截图 `41-crop.png`）：默认设置（关「无选项轮次间插入继续」）下，演到停止点只有一句「▼ 点击舞台继续」，右下角四个图标是插一句/改台词/重演/自动播放——**没有自由发挥、没有分岔**。而这恰恰是玩家最想介入的时刻，他必须自己想到去「路线」视图才能分岔。

`playbackState.ts` 的注释确认这是有意设计（「默认关是没有卡的」），所以这不是 bug，是**发现成本**：停顿处没有任何方向性提示。

**修法（建议级）**：停止点那一刻在台词条上给一行轻提示（如「想改方向？→ 自由发挥 / 路线分岔」），或者让导演栏在停止点时多亮一个「由此分岔」。

## P9　「OOC：」快捷前缀是圈内黑话

**现象**：「插一句」模态窗里输入框前挂一个 `OOC：` 药丸按钮，界面上没有任何解释，只有 hover 才有的 title。OOC = Out Of Character 是同人文/AI 角色扮演的圈内词，新用户大概率不知道按了会发生什么，触屏上更是连 hover 都没有。

**位置**：`apps/web/src/stage/StageTheater.tsx` 的 `OOC_PREFIX`。

**修法**：药丸改成有字的中文（如「按剧作家指示」），或至少在模态窗里补一行可见说明。

## P10　窄屏上选肢层几乎完全盖住立绘

**现象**（截图 `43-crop.png`，390x844）：三个选项卡竖排堆在舞台正中，把立绘从头到脚压在下面，只剩头顶露出来。竖屏本来就窄，选项层应该贴底排布或者给舞台留出上半屏，而不是压在画面中心。

## P11　润色会静默删掉玩家写的动作描写

**现象**：在「自由发挥…」里输入

```
我伸手，轻轻拉住她的袖口，说：明天放学，你能不能早点来。
```

点「润色」后变成

```
明天放学，你能不能早点来。
```

动作描写「我伸手，轻轻拉住她的袖口，说：」被整段吃掉。撤销能还原，所以功能没坏，但**润色的默认结果丢了玩家一半的输入**，而且没有任何提示。

**根因**：`apps/server/src/playhouse.ts` 的 `polish()` 系统提示第一句是「把玩家的原始输入改写成主角**会说出的台词**」，第三句是「只输出润色后的**台词本身**」。原输入里混了动作描写时，模型按「只输出台词」把它裁掉了。

**修法**：提示改成「改写成主角会做/会说的那一行」+「原文里的动作、神态、旁白一律保留，不要因为只输出台词而丢掉」。

## P12　「删除剧目」用 `window.confirm` 原生弹窗

**现象**：标题页「删除剧目」点下去走 `window.confirm`。这是全站唯一一个浏览器原生弹窗，视觉上跟自绘的 `ui/Modal.tsx` 完全是两个世界，而且原生弹窗没法做二次确认、没法统一 Esc 语义。

**位置**：`apps/web/src/views/TitleView.tsx:45`

**修法**：改走 `ui/Modal.tsx`，和其他破坏性/需确认的动作一致。

## 误判记录（留给后来人）

- camoufox 的 `snapshot` 只返回视口内可见节点：曾据此误判「回顾列表只有 1 条」，实际 DOM 里有 60 条且容器可滚。统计元素个数要用 `eval` 数 DOM。
- `element.click()` 不会触发阶段推进：`.theater-stage` 那个点击处理认的是 pointer 事件，要用 `camoufox-cli mouse click 640 350`。
- 工坊文件树的 `.file-row` 是 div，得点里面的 `.file-entry` 按钮才生效。
- 自动播放点两次 = on→off，不是 toggle 失效。
- 刷新测试时浏览器 daemon 挂过一次（`ECONNRESET`），`camoufox-cli --tab $TAB open <url>` 可以原地拉回来，不用重开 tab。
