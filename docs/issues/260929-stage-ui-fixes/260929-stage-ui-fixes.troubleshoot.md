# 舞台 UI 五处修复 排查

## 1. 工具条空闲自动隐藏

`StageTheater` 里有一个 `idleChrome` state 和 4 秒定时器：停手不动就加 `.chrome-hidden`（opacity 0 + 高度 0），必须 hover/点击才回来。这是桌面端「沉浸模式」的做法，被原样带到了手机上——手机上没有 hover，用户看到的现象就是「工具条自己消失了」。

修：删定时器与该 state。手动开关保留（桌面 H 键 / 手机在舞台上下滑），想藏时还能藏。

## 2. 手机上舞台左右露白边

`app.css` 里 `.screen` 给所有页面留安全区边距 `max(16px, env(safe-area-inset-*))`，而舞台页同时带 `.stage-screen` 类，命中的是同一条规则。安全区在无刘海/挖孔的机器上是 0，被 `max(16px, …)` 兜成 16px，于是满幅画面两侧各露一条页面底色。

修：`.stage-screen` 左右 padding 归零，只有普通页面留边。

## 3. 台词条一长就把背景和立绘挤扁

`.theater-dialog` 原本是 `.theater` 的 flex 兄弟节点（`flex-shrink: 0`），台词越长它越高，`.theater-stage{flex: 1}` 被顶得越来越矮——背景 `object-fit: cover` 跟着重新裁切，立绘按 88% 高度重算，等于整个画面随台词呼吸。

修：台词条改成 `position: absolute` 浮层（z-index 12），`.theater-stage` 独占工具条以下的全部高度，台词长短只影响浮层自己。

副产物：`.theater` 的背景色不再需要给台词条兜底，幕末黑场（`.act-curtain`，z-index 16）直接压在上面。

## 4. 那个「继续」按钮

两条来源，都通向同一个 `StopPanel` 分支：

1. **模型可以吐 `<stop type="pause">`**——DSL 允许三种 stop（choice/free/pause），pause 的语义就是「这一拍到此为止，请按继续」。模型爱用它来收尾，于是幕末就长出一个「继续」。
2. **编排器给空拍兜底时会伪造一个 pause stop**——拍里没解析出任何 stop 且不是幕末时，`finishBeat()` 会构造一条 pause 事件兜住，避免玩家卡死。

修：pause 类型从 spec / WS 协议 / 解析器 golden 用例里整个删掉（DSL v1 的标签集按约定「改集 = 改计划文档先行」同步改）。第 2 条兜底改为只发可恢复的错误提示，不再伪造停止点。幕末的正常出口是黑场 + 「下一幕」。

## 5. 幕末出现模型自己写的交代句

「第一幕圆满落幕…」「如需开启下一幕请…」这类文字是模型在 `<stop type="pause">` 之前自己加的旁白。stop 类型删掉后它没有出口可写，但提示词里仍在教它「结束节拍」该怎么说话。

修：`prompt.ts` 的「结束节拍」段改成明确禁令（幕末不写交代、致谢、期待、引导语，只把画面留在最后一帧），并补了反例；演出准则补一条禁止输出引擎状态行。

## 6. 排查中带出的两个附带问题

- **恢复会话会把上一拍的停止点复活到幕末**：`restoreStopPoint` 原来对整条 lineage 做 `findLast(stop)`。第二拍以 `act_end` 收尾时，第一拍的 choice 会被当成当前停止点，玩家看到黑场之前的旧选项——或者隔了一拍就作废的按钮。改为只在当前拍内（上一个 `beat_end` 之后）找停止点，找不到就是 `null` → 黑场 + 下一幕。
- **入戏输入行会盖住长台词的下沿**：台词条改成浮层后，输入行（z-index 14）压在它上面，5 行台词的最后一行正好落在输入行底下。改为输入行开着时台词条上移一行高（`:has(.stop-panel)` + 共享的 `--stop-h` 变量，安全区一并算进去）。
