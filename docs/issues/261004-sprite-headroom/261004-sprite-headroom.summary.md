# 立绘头顶留白：整体下移一档

## 问题

用户在手机与桌面两侧都觉得立绘太靠上。查 `packages/core/src/play/spriteStage.ts` 的预设表确认不是错觉：立绘图本身顶到画幅上沿（实测 `plays/mh` 三张 1080×1920 的 PNG，人物顶端到图像顶端只差 0.1~0.2%），所以表里的 `top` 就是头顶留白本身——横屏 normal 档 10%、竖屏 8%，读出来就是脑袋贴着天花板。

## 改动

- 预设表里**每一档贴头顶的行**（`normal` / `large` / `huge`，`small` 那三行贴地、不动）横竖屏两列统一下移 8：横屏 normal 10→18、竖屏 8→16，`large` / `huge` 同步。
- `height` 一个数没动——只平移不改大小，脚下被画面切掉的那截相应多切一点（而下沿本来就压在画面外或台词条后面，看不出来）。
- `spriteStage.ts` 顶部那句「缺省三档与加表之前的 CSS 完全一致」连同它背后的约束一起作废，替换成「头顶留白统一下移过 8」的理由。
- `test/spriteStage.test.ts`：原来那组「必须与旧 CSS 一模一样」的断言改成盯新契约（横竖屏 normal 档的留白值 + 每一档贴头顶的行都有留白），`small` 贴底那条不变式与对齐三档不变。
- `apps/server/AGENTS.md` 与 `README.md` 里「缺省逐数字与 261004 之前一致，存量剧目站位不能挪」的说法改成「改预设表等于动所有剧目的摆位，`top` 是头顶留白，已下移过 8」。

## 测试

`pnpm --filter @aivn/core test test/spriteStage.test.ts` 8 条全过；重建 core 与 web，`supervisorctl restart stage-ai` 后在 `plays/mh` 上实拍桌面（1280×800）与手机竖屏（412×839）两个视口，落位读数与表里的数一致（横屏 top 18% / height 132%，竖屏 top 16% / height 102%）。

## 验证

用户在手机与桌面上各看一眼立绘：头顶要有能看出的一截空，整体不再顶到天花板；台词条遮住的下半身本来就看不到，不必管切到哪里。
