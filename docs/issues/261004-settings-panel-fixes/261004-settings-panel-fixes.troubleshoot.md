# 设置页：保存误清凭据 + 保存按钮要滚到底 排障记录

## 现象

1. 已经配好的 API Key / 生图 Key，打开设置页**什么都不改**直接点「保存设置」，
   两把 key 都被覆盖成空串。访问密码同理：没设防时无所谓，设了防再点保存会被关掉。
2. 「保存设置 / 放弃改动」在设置页最底下，页面长，每次都要滚到底才按得到。

## 根因

### 凭据被误清

服务端契约（`apps/server/src/configApi.ts` 与 `configApi.test.ts` 用例）是：

- 读侧只回掩码（`sk-s••••1234`），明文不出服务端；
- 写侧「**回传掩码 = 不改**、清空 = 显式清除凭据」。

客户端却把两态混成了一个值。`SettingsScreen` 的 `draftOf` 把 `model.apiKey` /
`image.apiKey` / `password` 一律初始化成空串；其中 model / image 两个输入框还是
**非受控**的（只有 `placeholder` 摆掩码、没有 `value`），用户不碰它时草稿里就一直是 `""`。
于是「没填」和「不想改」在传输面是同一个值，服务端按契约把它当成「显式清除」——
点一次保存就把三处凭据清空。

顺带一个症状：非受控输入框在点「放弃改动」后不会回滚已输入的内容。

### 按钮要滚到底

「保存 / 放弃」那一行原本是 `.settings-body`（滚动容器）里的最后一个子元素，
自然要滚到底才看见。

## 修法（`apps/web`，服务端零改动）

- `draftOf` 不再抹掉凭据：直接把读视图里的**掩码**当草稿初值回填，三个单值凭据
  输入框改成受控（`value={draft.…}`），聚焦即全选（避免在掩码中间插字拼出一把坏 key）。
  - 保持原样保存 → 回传掩码 → 服务端判为不改；
  - 清空输入框 → 回传空串 → 显式清除；
  - 输入新值 → 替换。
  - 因为成了受控，「放弃改动」现在能把三个框真正回滚成上一次读到的掩码。
- 保存 / 放弃那一行移出 `.settings-body`，成为 `.screen` 的常驻页脚 `.settings-footer`
  （`flex-shrink: 0`），内容再长也不用滚；移动端安全区 `padding-bottom` 随之从 body 挪到 footer。
- 多把 key（语音 / 检索）语义不变：输入框恒空、留空 = 不改、填入 = 整组替换——
  它们本来就没有误清的问题（`mergeKeyList` 把空串当「不改」）。

## 改动面

- `apps/web/src/views/SettingsScreen.tsx`：草稿回填掩码、三个凭据输入框受控 + 聚焦全选、页脚拆出。
- `apps/web/src/app.css`：`.settings-footer` 规则、`.settings-body` 底部内边距收紧、安全区选择器换名。
- `apps/web/src/api.ts`、`README.md`（两处）、`apps/web/AGENTS.md`：把「输入框留空 = 不改」
  的旧说法改成单值凭据「掩码原样回传 = 不改、清空 = 清除」。
- 新增回归用例 `apps/web/test/settingsCredentials.test.tsx`。

## 关键约束（后续改动别踩）

- **凭据输入框的初值是掩码，不是空串**。谁再把它们改成 `""` 或改回非受控，
  这个「未触碰保存 = 清空凭据」的 bug 立刻回来。
- 服务端的判定是**字面比较掩码**（`patch.apiKey !== mask(config.apiKey)`），
  所以客户端必须原样回传读视图给的那串掩码，不能自己再加工。
- 多把 key 与单值凭据是**两套语义**（前者空串 = 不改，后者空串 = 清除），别顺手统一。
