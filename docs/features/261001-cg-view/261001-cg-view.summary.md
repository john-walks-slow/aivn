# CG 视图

需求：舞台外壳里加第五个视图「CG」，把这一场已经出过的插图列出来并能看到提示词；
路线视图的卡片在某一幕出过 CG 时优先显示那张 CG 而不是场景背景。

## 状态

已完成，等用户验收。

## 决定

- CG 页是**舞台外壳的第五个视图**（舞台 / 回顾 / 路线 / CG / 工坊），复用舞台那条 WS 连接与素材索引，
  不是独立路由页。直达地址 `#/play/<id>/stage?view=cg`。
- 台账只收**这一部剧目**的 CG：`plays/<id>/assets/cg/` 下的静态素材 + 站内生成到
  `plays/<id>/media-cache/img/` 的图。资源库 `library/cg/` 是跨剧目的，不进这一页。
- 服务端这一路**不建 runtime、不触发生图**：`readGeneratedEntries()` 直接读盘上的 manifest。
  打开这一页不该牵动演出那条线，也不该烧配额。
- prompt 在这里不藏：`ImageAssets.strip()` 对 WS 快照藏 prompt（那张是给渲染用的），
  但 CG 页是要给人读的台账，站内生成那张直接把生图 prompt 原文摊在卡上。
- 同一 id 静态素材优先（沿用 `assets.ts` 既有的素材解析优先级），但把生成记录里的 prompt 捡回来，
  这样「素材 + 有 prompt」两种来源的信息都不丢。
- 路线卡片背景：`(card.cgId ? index.cg(card.cgId) : null) ?? index.bg(card.sceneBg)`。
  `cgId` **不跨拍继承**——背景是持续状态（换幕后还挂着），CG 是插进这一幕的画。
  同一拍多张 CG 取最后一张：那是这一幕结束前屏幕上停着的那张。

- `packages/core/src/play/assets.ts`：`GeneratedImageEntry`（带 prompt 的生成图台账）、`CgEntry`（两类共用一个形态）。

- `apps/server/src/http.ts`：`GET /api/plays/:id/cg` + `cgCatalog()`（合并两个来源，按 id 排序）。
- `apps/web/src/api.ts`：`cgCatalog` 客户端。
- `apps/web/src/stage/CgView.tsx`：网格 + 灯箱（复用 `ImageLightbox`）。
- `apps/web/src/stage/view.ts` / `StageShell.tsx` / `views/StageScreen.tsx`：第五个视图与接线。
- `apps/web/src/stage/beats.ts`：`BeatCard.cgId`。
- `apps/web/src/stage/RouteCanvas.tsx`：卡片背景 CG 优先。
- `apps/web/src/app.css`：`/* ── CG 页 ── */` 一段。
