## 二、查过但保留（附理由）
- `SettingsScreen`：`留空或保持掩码即不改`、`≥ 网关会 400`、`必须小于压缩阈值`、`多把 key 轮询/留空=不改`、`模型 ID` 的清单来源状态 —— 约束与状态，非旁白。
- `Modal`/`StopPanel`/`RouteCanvas` 的动作 hint（`以主角口吻写一句。`、`回到这里：……不生成新内容`）—— 说清按钮到底做什么。
- `TitleView` 的缺失提示、`CgView`/`FileBrowser` 空态、`VoiceLibrary`/素材描述 —— 空态与数据，不是 blurb。
- `StageScreen` 路线页 `拖动平移 · 滚轮缩放 · 每张卡右下角就管这一段` —— 说明卡面不可点，属操作契约。

## 五、两份系统提示词是否值得大范围重写（2026-10-04 结论：不值得大范围重写）

规模：剧作家模板 ~3.7k 字符、搭台助手 ~4.3k 字符（不含注入的 premise / craft / 角色 / 素材清单）。
测试：`prompt.test.ts` 25 条、`workshopPrompt.test.ts` 6 条，多数钉的是真机踩坑得来的规则（静默降级不回执、neutral 与 normal 是两个名字、垫图是身份基准、edit_file 锚点要抄整行、谎报落盘的后果）。大范围重写等于拿这些重赌一次，而验证只能靠真机跑。

三个真问题（值得修，但不是「重写」）：
1. `beat_done` 的三种停法在 `prompt.ts` 的「你怎么工作」与「结束轮」各写一遍，`beatTool.ts` 的 `BEAT_DONE_DESCRIPTION` 又一遍——三处同义，正是 AGENTS.md 说的漂移源。
2. `workshop.ts` 硬编码了「玩家能打字的五处界面」（选肢层自由发挥卡 / 导演栏提示 / 停止点输入框 / 剧情选项 / 工坊对话）。UI 一改这段话就变假信息，且没有测试能发现。
3. 两个 prompt 都是一整个 template literal + 内联三元；只有 `AUDIO_RULES` / `LIBRARY_REF` / `imageGuide` 抽成了常量，其余章节没法单独测、单独改。

建议范围：抽章节常量 → 删 `beat_done` 重复（细则只留工具描述）→ 「能打字的五处」改为单一真相源或删掉 → 统一口吻；每步跑两条 prompt 测试，真机冒烟一次。

## 六、提示词结构整理（2026-10-04 实施记录）

按第五节的三条真问题做小范围整理，**不重写正文**（真机踩坑得来的规则一条不删）。

### 1. 章节抽成常量
- `prompt.ts`：`ROLE_INTRO`、`HOW_I_WORK`、`FORMAT_RULES`（DSL 格式章）、`NEW_CHARACTER_RULES`、`CONTRACT_RULES`（演出契约）。带能力位的仍走函数（`imageChapter`）与既有常量（`AUDIO_RULES` / `LIBRARY_REF` / `SEARCH_GUIDE`）。
- `workshop.ts`：`RESPONSIBILITY_RULES`、`TALK_RULES`、`IMAGE_BASICS`、`NO_IMAGE_GUIDE`、`LINEAGE_GUIDE`；带能力位的两章抽成 `setupFlow(canBrowseLibrary)` 与 `writingPoints(ctx)`（`assetSourceGuidance` 不变）。
- 装配模板现在只剩顺序与能力位开关。

### 2. `beat_done` 三种停法从三处降到两处
删掉「你怎么工作」里那段参数叙说（与下一节「结束轮」逐字同义），该节只留工作循环与「停止点不是终点」；`## 结束轮（beat_done）` 保留三种调用的硬契约与写法（`prompt.test.ts` 钉着这三条字符串），`agentkit/beatTool.ts` 的 `BEAT_DONE_DESCRIPTION` 保留为调用现场的参数说明——两边角色不同（契约 vs 工具），同义的第三遍没有了。

### 3. 「玩家能打字的五处界面」删掉
`RESPONSIBILITY_RULES` 里那条五条清单（选肢层自由发挥卡 / 导演栏提示 / 停止点输入框 / 剧情选项 / 工坊对话）改为不依赖 UI 形态的说法：
> 玩家能打字的地方都在舞台与工坊对话里；不确定界面上哪里有入口时，就说清要改什么，让用户自己找地方操作。

保留同段真正防错的那句：「路线」视图里没有输入框，只有两个按钮。

### 验证
- **渲染等价性**：临时快照用例把剧作家 6 组场景 + 工坊 3 组场景的渲染结果落盘，重构前后逐字符比对——除上述有意改动外完全一致；能力位两组（`canImage` / `canSearch` / `canLibrary` / `canGenerate` / `canBrowseLibrary` / `canVoices`）的开与关都覆盖到了。
- 测试：`prompt.test.ts` 25 条、`workshopPrompt.test.ts` 6 条、`agentkit.test.ts` 17 条全绿。
- 静态验证：本次改动的文件无类型错误；`apps/web` 的 `tsc --noEmit` 当前被另一处在途改动（NSFW 通道）挡住，`vite build` 通过。
