# 周目与路线树：现状考察

日期：2026-10-10
范围：stage-ai 当前实现；本轮只考察，不改代码。

## 结论

建议删除用户可见的「周目」概念，但不要把它理解为简单删掉 `saves/` 文件夹。

推荐的产品模型是：

- 一个剧目只有一棵谱系树。
- 路线树负责这棵树内的回看、分岔、重写、删除和历史浏览。
- 「从头重开」变成根节点上的一次显式新运行，不再另开一页周目管理。
- 内部仍需要一个“新运行”语义，不能让普通的「继续」承担它。

原因：当前周目并不是一个完整、独立的世界线容器。它只隔离谱系和引擎快照，剧目记忆、状态文件工作面、素材和工坊线程仍是剧目级；同时路线树已经覆盖了大部分玩家需要的历史探索能力。

## 两个概念当前各自是什么

### 周目

`apps/server/src/saves.ts` 将周目实现为存档位：

- `plays/<playId>/saves/<saveId>/` 下有 `meta.json`、`session.json`、`lineage.jsonl`。
- `active.json` 指向当前活动档。
- `PlayStore` 以 `saveId` 作用域保存谱系和引擎会话。
- `PlayHouse` 通过 `createSave`、`switchSave`、`deleteSave` 管理整棵树。
- 档名只是标签，不是故事身份。

这不是“周目”通常带有的完整新游戏语义，而是多棵独立故事树的管理层。剧目包导入/导出也不包含周目故事树，见 README 的剧目包说明，因此它也不是一个可携带的传统存档。

另外，共享包 `packages/core/src/play/config.ts` 里的 `newGamePlus` 使用「周目」表示另一套语义：同一工作区的新会话，以及 `endings.json` 的跨会话结局账本。stage-ai 的 `saves` 语义与 DSH 线的 `newGamePlus` 语义并不相同，共享包里的命名会造成混淆。

### 路线树

路线树不是第二份存档数据。它是 `LineageTree` 的投影：

- `packages/core/src/lineage/model.ts` 保存 append-only 事件和 `parentId` 分支关系。
- `LineageView` 输出全量节点、当前路径和叶节点。
- `apps/web/src/stage/beats.ts` 将行级事件聚成“一拍一卡”。
- `RouteCanvas` 将拍卡布局并映射到 `jump`、`fork`、`delete_branch` 等结构操作。

路线树的职责是：

- 我现在在哪条路上。
- 过去从哪里分岔过。
- 回看旧点。
- 从旧点重写并开新枝。
- 删除某个子树。

所以它与周目不是同一层的数据概念，但两者都让用户执行“回到过去、再走一遍、保留另一种结果”。在生成式剧情里，路线树已经是更直接的探索界面。

## 是否重复

### 数据层：不重复

周目提供独立根和整棵树的生命周期；路线树提供一棵树内的节点、分支和结构操作。删除一个周目会删除整棵树，删除路线树分支只剪当前树的一部分。

### 产品层：有重叠

当前用户路径是：

1. 剧目标题页进入「开始/继续」。
2. 周目页选择一棵树。
3. 舞台侧栏打开路线树。
4. 路线树再完成回看、重写、分岔和删除。

对于“我想从某个选择重新走一条路线”，路线树已经足够。周目的独特价值只剩：

- 把一整次运行从路线树中分离出去。
- 不让旧分支继续堆在同一张树里。
- 让整棵独立树有一个批量删除边界。

但当前周目不能同时承载两条运行：`PlayHouse` 按剧目只缓存一个 runtime，切换周目是切换整个剧目 runtime，而不是两个玩家并行进行。因此它不是并行会话系统。

## 记忆管理风险

### 路线树的风险

路线级的部分目前已经有正确方向：

- `LineageSnapshot` 保存 engine、`stateFiles`、compaction、nsfw 等分支事实。
- 纪元压缩记录随谱系快照走，不再写成剧目级 `memory/arcs/` 卡。
- `search_archive` 通过 `tree.pathSet()` 过滤兄弟和废弃分支，避免模型直接召回别的路线。

仍然存在的问题：

1. `memory/index/**` 是剧目级共享卡。分支 A 中写入的剧情事实会进入剧目级 A 区，分支 B 每轮也能看到。`docs/features/261004-memory-curator/261004-memory-curator.plan.md` 已把它列为未解决的分支剧透风险。
2. 剧作家仍可通过通用文件工具写入 `memory/index/**`。如果模型把“某条分支刚揭示的事实”写成设定卡，路线过滤会被绕过。
3. `memory/archive/events.jsonl` 是剧目级 append-only 文件。剪枝后死切片仍留在文件和 MiniSearch 输入中；检索时只是不可命中，不是物理回收。
4. `memory/always/state/*` 是一份剧目级工作态文件，真实分支状态在谱系快照里。跳转或切换时由当前路径快照回写工作文件，通用文件写入与引擎回写之间存在覆盖语义。

### 周目的风险

周目把上面的边界再放大了一次：

1. 周目 A 写入的 `memory/index/**` 会被周目 B 的剧作家每轮注入。可见语义是“剧目级正典”，但用户看到的是“独立周目”。
2. 所有周目的 archive 切片都进入同一个 `memory/archive/events.jsonl`。切换周目时由于节点 id 不同，旧档通常不可召回，但旧切片仍被加载、索引和长期保留。
3. 删除周目只删除 `saves/<saveId>/`，不会删除该周目的 archive 切片。
4. state 文件只有一份，当前活动周目重建时会回写它；切换和重建本身是正确性边界，不应再让通用 `write` 随意修改这类引擎工作态。
5. `deleteSave` 目前先删除目录，再处理 runtime，没有像 `switchSave` 那样先等待 `orchestrator.whenIdle()`。进行中的异步持久化可能在删除后重新创建目录。这是独立 bug，不是产品命名问题。

### 共同根因

不是“周目和路线树同时存在”本身造成记忆混乱，而是不同生命周期的数据没有统一的 scope 契约：

| 数据 | 当前物理范围 | 实际应表达的范围 |
|---|---|---|
| `memory/always/premise.md`、`craft.md` | 剧目 | 剧目作者设定 |
| `memory/index/**` | 剧目 | 只能放作者正典，不应承载分支剧情事实 |
| `LineageSnapshot.stateFiles` | 谱系节点 | 当前分支事实 |
| compaction | 谱系快照 | 当前分支上下文投影 |
| `memory/archive/events.jsonl` | 剧目单文件 | 当前谱系的可检索历史，需按节点过滤和回收 |
| `memory/always/state/*` | 剧目单文件工作面 | 当前活动路径的工作态，不应被当作普通记忆卡编辑 |
| `session.json`、`lineage.jsonl` | 周目 | 独立运行的谱系事实 |

删除周目会消除“跨周目共享 index/archive 的错觉”，但不会自动修复路线树内的分支剧透，也不会自动让 state 和 archive 有正确的物理生命周期。

## 为什么倾向删除用户可见周目

- 路线树已经是玩家探索分支的主界面。
- 周目当前主要是存档分组，不是完整的新游戏系统。
- 周目不可导出，且不支持同剧目并行运行。
- 单树模型可以把“新的一局”表达为根节点下的新枝，路线树本身就能展示它们的关系。
- 少一套 UI、REST、WS 状态和 runtime 切换生命周期。
- 消除 `saves` 语义与共享包 `newGamePlus` 语义的产品词冲突。

## 需要正面接受的代价

- 多次重开会让同一棵路线树变大。
- 用户不能一键把一整次运行从树上隐藏，除非补一个“根分支/运行组”视图或整棵子树操作。
- “从头重开”不能直接复用普通 `continue`：当前 `revisitOldPath` 会优先走已有路径。必须增加显式新运行原语，明确绕过旧路复用，并从 `play.initialState` 初始化。
- 需要路线树在长树上的折叠、只看当前运行、或节点虚拟化等后续治理。

## 判断

可以删除的是用户可见的“周目页/周目切换”概念，不是把“新运行边界”也删掉。推荐将新运行收敛为路线树根部的一次显式操作，并把记忆 scope 单独修正。
