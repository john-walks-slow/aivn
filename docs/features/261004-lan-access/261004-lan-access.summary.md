# 局域网访问：总结

提交 `68e0467`（2026-10-04）。

## 做了什么

装完默认监听 `0.0.0.0`，局域网能不能连全看用户在 Windows 防火墙弹窗上有没有点「允许」。点过「取消」会留下一条阻止规则、之后不再弹，用户只会觉得软件坏了，而补救要在管理员命令行里敲 `netsh`。改防火墙必须有管理员权限，我们是 per-user 安装（全程不弹 UAC），安装时静默写规则这条路走不通——所以把这件事收回应用里。

- 新设置项 `lanAccess`（默认关）：关着只听 `127.0.0.1`，开着听 `0.0.0.0`；显式 `--host` / `STAGE_HOST` 仍然优先（dev 脚本显式带 `0.0.0.0`，行为不变）。
- 改开关**就地重绑**监听地址、端口不动。有活动 WS 时 `server.close()` 的回调永远不来，所以先 `terminate()` 掉 WS 客户端再 `close()`，另加 100ms 兜底强制收连接；页面自己重连。
- `GET /api/config` 的 `bootstrap` 回报**实际**监听地址与端口（顺手修掉「8787 被占时设置页显示的是配置值」），以及手机该连的那几串地址。
- `POST /api/lan/open-firewall`：只认本机请求，提权写一条**按程序**的入站放行规则——服务端口会漂，按端口写迟早失效；先删同名再新增，重复点是同一条。
- 设置页新增「局域网访问」一组：开关、地址逐条复制、放行按钮。
- README 字段总表、安装与手机两节、`--host` 默认值说明一并改口。

## 行为变化

新装默认只听本机，要连手机得去设置页把开关打开。局域网可用从「默认暴露」改成「用户点头」——之前只要弹窗点了允许，同一个 Wi-Fi 下任何人都能进这个没设密码的入口。

## 验过的

Linux 上（`docs/features/261004-lan-access/261004-lan-access.validation.md` 记的操作口径之外的自动化部分）：

- `pnpm -r build` / `pnpm typecheck` 全绿；定向用例 56 passed（另 settingsStore 9 passed）。
- 真起服务：默认 `127.0.0.1` + `lanUrls` 空 → `PUT lanAccess:true` 就地改听 `0.0.0.0`、端口不变、`lanUrls` 出地址 → 关回去同理；`settings.json` 落盘一致。
- 局域网来源调放行接口 403，dev 态 501；端口被占时 `bootstrap.port` 回实际端口。
- 持着活动 WS 切开关：WS 断开并在重绑后重连成功，不可达窗口约 123ms。
- Windows 真机：装好后应用起在 `127.0.0.1:8787`（新默认生效），局域网地址连不上。
- Windows 真机（开关打开后）：就地改听 `0.0.0.0:8787`、端口不变、手机 `GET /api/plays` → 200。
- Windows 真机（点过「取消」的现场）：本机确实有两条系统自动生成的 `aivn-server.exe` **阻止**规则，它们在位时手机超时；修复后的脚本按应用同一种调用方式跑过——退出码 0、阻止规则归零、手机立刻 200。

## 实机撞到的坑（这次改动的直接动机，差点白做）

`openFirewallRule` 原先只做「删自己那条同名规则 + 加一条 Allow」。真机上撞到：用户在弹窗上点「取消」时，**Windows 自己会写一条以程序命名的入站阻止规则**，而显式阻止的优先级高于放行——于是开关开着、放行规则已启用，局域网依旧连不上，按钮还会回报「已放行」。本机上就有两条这样的规则（历史的两次取消），删掉立刻通。

修法是把「清掉同程序的入站阻止规则」并进同一段提权脚本（`firewallRuleScript`，纯函数、有单测盯着这一步不许被简化掉）。这条只有真机才撞得到：Linux 上没有防火墙这一层，任何在开发机上跑的模拟都验不出来。

## 没验的

- **放行按钮的 UAC 那一跳**没有实机点过：提权脚本本身、规则落盘、以及「清阻止规则 → 手机立刻能连」都验过了，但「在页面上点按钮 → 弹 UAC → 点『是』」这一跳要人点，自动测不了。
- 手机连上的那两步是间接验的（手机 curl 到 PC 拿到 200），没有真在手机浏览器里打开过页面。
- 关掉开关后立刻断开这一条没在 Windows 上走（Linux 上验过）。

## 遗留

- 桌面壳标题栏只在启动时就绪窗口内抓一次 stdout 的「局域网 …」行；运行中打开开关会打印同样的行，但标题栏不会实时更新。没动 `apps/desktop`（超出本功能范围）。
