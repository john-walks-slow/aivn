# 局域网访问：要你实机确认的几件事

自动化能覆盖的都在 Linux 上跑过了：默认只听本机、开关打开后就地改听 `0.0.0.0` 且**端口不变**、局域网来源调放行接口被 403、dev 态回 501、指标回显给的是实际绑定端口、带着活动 WS 切换开关能自己重连。

第 3 条（点过「取消」之后救回来）已经在 PC 上撞到并修过一轮，见文末。

## 1. 新装默认只有本机能连

装完不碰设置，手机连同一个 Wi-Fi 打开 `http://<电脑IP>:8787` —— **应该连不上**（这是这次刻意改的默认值，关着时服务端只听 `127.0.0.1`）。电脑上的窗口自己一切正常。

## 2. 打开开关就能连

设置页 →「局域网访问」→ 勾上「允许局域网访问」→ 保存。

预期：网页掉一下线自己连回来（端口不变）；Windows 弹一次「是否允许访问网络」，点**允许**；设置页「手机该连的地址」列出 `http://<电脑IP>:8787`，手机打开它能看到剧目库。

## 3. 当时点了「取消」也能救回来

这条是这次的重点。先在弹窗上点**取消**（手机此时连不上），再点设置页里的「允许局域网访问（Windows 防火墙）」：

预期：弹 UAC → 点「是」→ 页面回一句「已在 Windows 防火墙里放行…」→ 手机能连了。**再点一次不报错、也不堆第二条规则**（规则名固定是「AIVN 局域网访问」）。

## 4. 关掉开关立刻断开

取消勾选并保存：手机上刷新应该立刻连不上，电脑上的窗口照常用。

## 附：自查

「Windows Defender 防火墙 → 高级设置 → 入站规则」搜 `AIVN`，应该只有一条「AIVN 局域网访问」；**不能再有**名字就叫 `aivn-server.exe` 的入站**阻止**规则——那是系统在弹窗上点「取消」时自己写的，显式阻止优先于放行，它在就永远连不上。

## 已经在真机上走过的部分（2026-10-04）

- 装好的应用默认是 `127.0.0.1:8787`，从手机打过去连不上 ✓
- 开关打开后应用就地改听 `0.0.0.0:8787`（端口不变），`lanUrls` 出地址 ✓
- PC 上确实存在两条系统自动生成的 `aivn-server.exe` **阻止**规则（本机历史上点过「取消」留下的），它们在位时手机**超时**；删掉立刻通 ✓
- 修复后的脚本（先清同程序阻止规则、再删同名、再写放行）用应用同一种调用方式跑过：退出码 0、阻止规则归零、随后手机 `GET /api/plays` → 200 ✓
