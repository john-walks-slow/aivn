# 看图工具通用化（view_image）

## 问题

两件事绑在一起，都是「看图被当成了出图流程的一环」。

**一、`inspect_asset` 只能看剧目内的图。** 名字与实现都锁死在 `assets/**` 白名单里，模型看到一张网络图片的
URL 也没有办法把它读进来。于是「用户提一个角色 → 去搜她的图 → 照着那个画风给剧目定妆」这条路断在最后一步：
搜得到 URL，看不到像素。能拿到的只有网页对那张图的文字描述。

**二、系统提示词规定「出完立绘必须看一遍并逐条核对」。** 每张图一次 `inspect_asset` 就是一轮里多一张
base64 图片（一轮 1080x1920 的 PNG 编码后几百 KB），出三张差分就是三份。这条规则是当初为了治
「agent 看过图仍然汇报『已严格按设定完成』」写的，但它把「什么时候需要看图」写死成了「每次出图都要看」——
而多数时候模型看一眼也看不出什么，纯属白烧。

## 方案

**工具：把 `inspect_asset` 换成 `view_image`。** 一个 `source` 参数吃两种来源：

- 剧目内相对路径（PlayFiles 白名单，和原来一样）；
- http(s) 网址 —— 新增的 `webImage.ts` 下载，按 URL 摘要缓存到 `plays/<id>/media-cache/web-images/`，
  同一网址再看一次直接读缓存。

**提示词：删掉那条核对流程。** 出图章节里「立绘出完逐条核对再汇报」整条拿掉，连带 `recut_sprite`
的提法（那是工具知识，该待在工具描述里）。`sprite-differences` 技能里那节从「出完立刻看一遍」改成
「看图能看出什么」，保留判断清单，去掉触发条件。

## 决定

- **不新开配置项**（用户 2026-10-03 定的）。出口代理读标准的 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量，
  取第一个非空的；没有就直连。超时是模块常量 20s：一个下载不该带一个可配的旋钮。代理本来就是环境的事，
  装服务的那台机器上设一次就有——为此专门加一个 `STAGE_*_PROXY`，等于要求用户记得去设置面板里填一遍。
- **SSRF 边界在 `webImage.ts` 里**。地址是模型给的：页面正文里写一句「参考 http://127.0.0.1:8787/api/config」
  就可能真的去取。所以下载前解析域名，逐个地址判公网（回环 / 私网 / 链路本地 / 云元数据 169.254.169.254 /
  运营商 NAT / 组播 / v4 映射的 v6 两种写法），`localhost` / `.local` 在解析之前就拒，
  非 http(s) 协议直接拒，**每跳重定向重判**（只查首跳是最常见的绕过）。上限 20MB、跳转 3 跳。
- **不静默降级**。非图片、HTTP 4xx/5xx、超过上限，都把可读的原因回给模型，由它决定要不要换个来源。
- **缓存按 URL 摘要**而不是按内容：判存在发生在下载之前，否则「重复看一眼」照样要下一次。

## 验收

- `apps/server/test/webImage.test.ts`：内网/回环/链路本地/v4 映射 v6 全部拒，localhost 名字在 DNS 之前拒，
  `file:` / `data:` / `gopher:` 拒，不是网址直接报错，DNS 失败照实说，缓存名同址同值异址不同。
- `apps/server/test/workshop.test.ts`：本地路径读成 image attachment 且字节一致；非图片字节不塞进模型；
  网址分支下载 → 读进模型 → 落在 `media-cache/web-images/` → 同一网址再看不再下载；
  没有下载器时网址分支回「未启用」而不是报一个必然失败的错。
- prompt 用例改成反向断言：出图章节里不再出现 `view_image` / `inspect_asset` /「逐条核对再汇报」。
- 真机单点验证（2026-10-03，走真实代理）：`https://httpbin.org/image/png` 直出 8090B PNG；
  `https://picsum.photos/200/300` 经 302 跳转拿到 14742B JPEG——重定向链路是真的通。
