# 一轮写不出来时的兜底（判废 · 回滚 · 重演一次）实施摘要

## 做了什么

剧作家这一轮**没写出任何可演内容**时，不再把它当正常一轮收下，而是当它没发生过：

1. **判据换硬事实**：删掉 `beatEvents`（事件数）计数，改成「零台词（say/narrate/thought 一条非空的都没有）
   且没有交出停止点」。旧判据数事件，而 `scene/actor/sfx/cg/preload` 都算事件——
   「改了背景 + 裸散文拒答」「只发起一张图、零台词」这类轮次护栏不响，玩家拿到空舞台还被写进谱系与快照。
2. **判废即回滚**：复用上下文重建（`rebaseAt` 的执行体抽成 `rebuildBranchAt`，判废退回与玩家分岔共用一份实现），
   但不落 fork 标记、不写 `beat_end`、不存快照、不切 archive——这一轮不进档。客户端整段重放，
   判废前已经流出去的那半截也从台上一并消失。
3. **原样重演一次**：`beginBeat` 从「跑一轮」变成「跑到不必再跑」。
   同一段输入（steer + 选择一起）逐字重发，不塞格式纠偏的新指令——把「不肯写」当「格式错」推它继续写是另一条路。
   上限 1 次。**超时不重演**（网关挂住是路不通，重演只是让玩家再等一个超时）。
4. **二次失败进失败态**：退回「这段输入还没发出去」的那一刻——上一轮的停止点连同选项原位复原，
   本轮注入的 steer 复位成 pending 放回队首（id、改过的文本都不变），报错发在 `rebase` **之后**
   （客户端的 rebase 处理会清 error 状态）。
5. **退回处必须留一个出口**（真机验证抓出来的阻塞缺陷）：上一轮是 `no_stop` 收尾时，退回后没有停止点，
   而 `onBeatSettled` 的判据是「没有停止点 + 队列里有待注入的输入 → 自己开下一轮」；
   判废退回恰好把引导放回了队列——两者一撞就是**失败自我循环**（每 10~15 秒烧两次调用）。
   现在退回后若没有停止点就补一个 `pause` 出口，断掉这条环；上一处本来有真选项时不动它。

## 决定与代价（已与用户对齐）

- **不做拒答文本启发式**：判据只兜「有没有可演的产出」这件硬事实。包进 `<narrate>` 的拒答照常上演——
  误杀（角色台词里说「抱歉」）比漏判贵得多。
- **不剪枝**：判废的节点留在谱系里当废弃分支（与「重来这一轮」同性质），append-only 与 JSONL 游标都不动。
  代价是路线视图里会出现一张没台词的废弃卡。
- **判废那一轮的副作用不撤销**：已经发起的生图仍会出完并落进 `assets/`（台面事件消失，配额已经花掉）。
- **有台词但有报错/超时的轮不判废**：不回滚不重演，内容留着。
- 作废那一轮的解析告警不回灌（回灌只会把拒答原文塞回上下文）。
