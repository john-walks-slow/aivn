# 一轮写不出来时的兜底（判废 · 回滚 · 重演一次）用户验证

## 验证说明

- 验证对象：剧作家这一轮**没写出任何可演内容**（拒答成散文、只调工具、provider 报错、超时）时，
  引擎会不会把这一轮当没发生过——回滚、原样重演一次、还不行就把选择权还给玩家。
- 为什么要验：三种「写不出来」在真机上不好摆（模型拒答不可控），但**后果**都走同一条路。
  开发侧已用「网关必然报错」的剧目把这条路径在真机上跑通（见下表「开发侧实测」）；
  下面「待验证」的部分请你在真机上按自己的剧目过一遍，重点看**舞台与队列的实际手感**。
- 环境/前置条件：stage-ai 服务端在跑；剧目能出词（模型可用）；一个至少演过一轮、有停止点（选项或自由输入）的周目。
- 公网验收入口（开发实例，随进程失效）：`https://<quick-tunnel-domain>`（本次实测用的是本机 dev 实例，
  server `127.0.0.1:44732` / web `127.0.0.1:59181`；两个端口都是 acquire-port 现取的）。

## 验证项

| 验证步骤 | 预期结果 | 实际结果 | 状态 | 备注/证据 |
| --- | --- | --- | --- | --- |
| 开发侧：把剧目 `agents.playwriter.model` 指成一个不存在的模型 id（网关必然 400），点「开演」 | 这一轮**什么也不演**（舞台上没有凭空出现的旁白/台词），报错一条，给一个 pause 出口 | 与预期一致：台词条停在「（点击开始）」，一条 `本轮生成失败：400 …model_not_found` error，`点击舞台继续生成` | 已通过（开发侧） | 首轮没有输入节点可退，走的是「退不掉就就地收尾」那条路 |
| 开发侧：在同一周目排队一句引导（插一句），再点舞台继续 → 连失败两跑 | 第一次失败即**回滚到本轮开头原样重演**（客户端整段重放 + 一句 warn 说明），不额外塞新指令 | 与预期一致：warn `本轮没有写出内容，已退回本轮开头原样重演一次` 恰好一条，客户端 epoch+1 重放 | 已通过（开发侧） | 重演发出的是**同一段原文**（stream 调用 2 次，user 文本逐字相同） |
| 开发侧：上面那次重演也写不出来 | 退回「这句引导还没发出去」的那一刻：报错带上「已自动重演一次」，**并且不再自己往下开轮**（否则失败会自我循环） | 与预期一致：error 一条带「（已自动重演一次，仍未写出内容）」；`beatNo` 退回 1、`lastStop=pause`、epoch=2、events 清空、历史回到 1 轮；随后 60 秒内 toast 不再增加、无新一轮 | 已通过（开发侧） | 证据见本目录 `screenshots/01-failure-state.png`；死循环是本轮真机验证抓出来的，修复见计划 §5 |
| 开发侧：判废退回后看谱系与存档 | 判废的那一轮不进谱系主路径、不写 `beat_end`、不存快照、不切 archive；只有一条废弃分支 | 与预期一致：`lineage.jsonl` 尾部是上一次 `beat_end` + 那一条 `prompt`，没有失败轮的 `beat_end`；`events=[]` | 已通过（开发侧） | 废弃节点仍留在谱系里（路线视图会出现一张没台词的废弃卡，已接受） |
| 真机：拿你自己的剧目，在停止点上插一句**明显越界/过激**的引导，再点一个选项 | 剧作家若拒答（裸散文被丢弃、或只调工具）：舞台**不会**把拒答文本演成台词；这一轮重演一次；仍然写不出来就报错、选项原样回来、你插的那句**回到待注入队列**（可改可撤） | | 待验证 | 拒答成 `<narrate>` 的旁白**会照常上演**（引擎不猜语义，见计划「决定」） |
| 真机：把这一轮拖到 provider 真的挂掉（断网 / 换一个不可用模型 / 撞 429）后重试 | 同上报错路径；`error` toast 常驻不自动消失，点掉即可；「继续」能重开一轮 | | 待验证 | |
| 真机：让一轮**跑到超时**（`STAGE_BEAT_TIMEOUT_MS`，默认 240s） | 回滚 + 报错 + 交还出口，但**不自动重演**（网关挂住是路不通，重演只是再等一个超时） | | 待验证 | 与「报错类失败」的唯一差别就是不重演 |
| 真机：一轮里已经写出台词、之后才报错/超时 | 不回滚、不重演：内容留着，照旧报「本轮生成中断」 | | 待验证 | 把玩家已经看过的内容抽走比留着更糟 |

## 待跟进

- 判废那一轮的**副作用不撤销**：如果这一轮已经发起过生图（`generate_image`），图仍会出完并落进
  `assets/`（事件从舞台消失，但后台任务与配额已经花掉）。同一张图重演时不会重复出（按素材名去重）。
- 报错 toast 里是 provider 的原文（长、带 JSON）。这是既有行为（旧护栏也是这么报的），本次未改；
  嫌吵可以后续单独做「provider 错误人话化」。
