## 二、逐条诉求核对

计划把它记为关联、未改动，正确。上一轮的 `261004-route-branch-jump.summary.md` 有实测与截图，我不再翻旧账。

### ② 回到旧轮走原路 —— 方向正确，但有坑

- **病根判断对**：`playerAction` 拿到动作就无条件开新一轮（`orchestrator.ts:810-814`），从没查过"这个挂载点下有没有同一条来源的现成下一拍"。这条诊断成立。
- **"来源标签 + 最后去过优先"符合我的直觉**：我用同一个选项回去，本来就该接着上次那条枝读；我也确实说过"同一条枝上重写过的也要认，认最后去过的那条"。规则 1/3/4 是照着我这句话来的，认。
- **但 `prevLeafId` 不是字面上的"最后去过"**：它是"**上一次显式结构操作（jump/fork）之前的世界线末梢**"。二者只在"想回去就必先 jump/fork"这个前提下等价。计划里没把这个前提写明，读起来像是真在跟踪"去过哪些枝"。这条要按 M3 收紧（补生命周期 + 补测试），否则实现的人会按字面理解去写，后面再改就是返工。
- **一个会真炸的边界**：重写会产生一个带 `origin` 的 `fork` 标记节点，而删除（本轮新增）删的是"卡片首节点及其后代"——**fork 标记不在卡片里**，删完会留下一个空壳 fork。它来源标签与旧枝相同，正是规则 3 的候选；`beatEndFrom` 沿着空子树走会当场没解。这是本轮两条新能力（复用 + 删除）交叉出来的新 bug，计划没覆盖。见 M1/M2。

### ③ 分支线看不清 / 点击 node 选中 —— **这里有理解偏差**

- 线加粗、端点圆点、废弃枝提亮：认可，是"看不清"的正解之一，且便宜。
- **「选中」被设计成纯视觉标记（计划 103 行原话："当前只是标记"），这是把用户诉求做小了。** 我原话是"分支线看不清，希望点击 node 可以选中"——两句是一件事：选中是为了**看清"这条线通到哪、这条枝与我什么关系"**。点了只是卡片描个边，我点两下就会觉得这功能是半成品。
- 拍板见第四节，最小必须做到：**选中即高亮该段所属枝的连线（祖先链 + 子孙链），且同时把"删除会波及的范围"照出来**。这两件事是同一次子树遍历，几乎是白送的，且把"删除删的到底是哪一段"这道我最担心的题，在动手之前就摆到我眼前。

另外计划 102 行写"把 `route-dot` 真正用起来"——它**现在已经在用**（`RouteCanvas.tsx:262-272`，给 on-path 卡片中心画点）。措辞与代码不符，实现的人可能照着这句话再画一套圆点。改为"把端点圆点从卡片中心挪到连线的子节点端"才准确。

### ④ 三个动词 —— 方向对，交互没写

改名、动作收敛（`jump` / `rewrite` / `remove`）我认。缺的正是**交互层**：点"重写"之后指令框长什么样、能不能留空；点"删除"之后弹窗说什么、删多少。见 M4 / M6 / 第五节。

计划对后端（规则、原语、测试）想得很清楚，对 UI 只有一行"复用 `ui/Modal.tsx`"。用户点名的三个动词里，两个带交互（重写要输入、删除要确认），选中态的意义也没定。按我原话的口径，这还不算"想清楚"。

## 三、必须修改项（动工前补齐，否则打回）

### M1. 删除必须处理"空壳 fork 标记"

`removeSubtree(nodeId)` 只删 `nodeId` 及其后代；而 fork 标记是卡片首节点的**父**（`beats.ts:112-120`，fork 节点不进 `card.nodes`）。删掉一条重写出来的枝后，树上会留一个无子节点的 fork 标记。

必须二选一（建议都做）：
1. `removeSubtree` 结束时上溯父节点，**删掉变成空壳的 fork 标记**（连带清快照）；
2. 旧路复用规则里把候选限定为**子树有内容**的节点（`beatEndFrom` 有解），空子树一律不参选。

理由：不清它，下次我回到同一个锚点选同一个选项，命中一个空节点，行为未定义。

### M2. `beatEndFrom` 的兜底语义要写死

计划只说它"停在三处"。加第四条：**沿唯一子节点走不到任何 `beat_end`（子树为空/被截断成空）时**返回什么（抛错？返回自身？返回 null？）必须写明，且旧路复用侧必须防御。补对应单测（空子树、fork 截断、多子截断、异常）。

### M3. `prevLeafId` 的生命周期补齐

计划只说了"jumpTo / forkTo 进入时记一次"，缺三件：
- **删除时**：被删子树里若含 `prevLeafId`，要清掉或回落到 `nodeId.parentId`（悬空引用会让"含 prevLeafId 的候选"永远判不出，静默退化到"最新创建"，行为变得不可预期）；
- **读档时**：`session.json` 里没有这个字段（旧档）或指向已不存在的节点 → 一律按"无偏好"处理，不得当成命中；
- **`deleteBranch` 自己**也是一次结构操作：它算不算更新 `prevLeafId`？写明（我倾向算，因为世界线确实被挪了）。

补测试：连续两次 jump；删除掉含 `prevLeafId` 的枝后再复用；旧档无字段。计划第 114 行的测试清单把"最后去过"缩成了"先跳走再回来选同选项走最近那条"，**不够**。

### M4. 「重写」的指令输入必须写进计划，且语义要如实

- 交互：点卡片"重写" → 复用 `ui/Modal.tsx` 弹输入框（与舞台导演栏同一手感），**允许留空 = 纯重写**，填了 = 带一句指令。这条现在完全没有。
- 语义：计划 81 行说"和舞台「重来」同一条路：`fork` + 排队 `prompt`"，而 `StageTheater.tsx:499-504` 的现状是**先 `onFork(beatId,{resume:true})`、后 `onPrompt(text)`**，指令是**在重写那一轮已经开跑之后**进队列的，最终落点是"重写之后的下一轮"或"与我的下一次选择合并"，**不是**写进被重写的那一轮（`forkTo` 的续演注入恒为空：`orchestrator.ts:980`）。
  - 我接受"与舞台一致"（这是我原话要求的），但计划里"紧跟着落进重演的那一轮里"这句和实际不符。**要么把措辞改成实际语义，要么明确改动行为**；二者选一，并各配一条测试锁定。
  - 建议（不强制）：既然它实际是"下一次开口时生效"，卡片上就写"重写这一段，并交代一句"，别让人以为指令会立刻改写那一轮。

### M5. 「选中」必须承载信息

最低要求：
- 选中时高亮该段所属枝的连线（祖先链 + 子孙链），而不只是给卡片描边；
- 选中时把**该段及其全部后代**（= 删除会波及的范围）用可辨的方式标出来；
- 与现有 `live` / `here` / `dead` 三态样式分层清楚——现在 `on-path` 与 `isLeaf` 已经各占一套视觉，再加一个 accent 描边必须能一眼区分，不能糊在一起；
- 点空白 / `Esc` 取消（计划已有），另确认抬 `z-index` 之后卡内按钮仍可点。

### M6. 三个动词的文案要写死"生不生成"

现在卡片按钮的 `title` 是唯一解释处（`RouteCanvas.tsx:338/348/358`）。改名后必须明确区分，且写进计划而不是留给实现随手编：

| 动词 | 一句话语义（要落到 title / 悬停提示） |
| --- | --- |
| 跳转 | 回到**这一段**的开头，从头演一遍（**不重新生成**，选项照旧） |
| 重写 | 退到这一段之前，让剧作家**重新生成**这一段（原内容留作旧枝；可交代一句） |
| 删除 | 剪掉这一段**以及它之后长出来的全部内容**（需确认） |

两个提醒：
- "跳转"在卡上是"回到**这一段**（这一轮）的开头"，不是歧义的"本轮"——按原话写文案会在卡片语境里读错；
- 计划 79 行说删掉"回到选项"是因为"与跳转重叠：跳转过去读到末尾，选项自己会摆出来"。**这话说轻了**：一个是秒到选项，一个是把整轮重读一遍。我要删这个按钮是我自己点名要的（三动词极简），我认；但计划要**如实承认这是一次"用整轮重读换掉秒到选项"的取舍**，并且它成立的前提正是本轮②把"同选项走原路"修好了。别把取舍写成"重叠"。

## 四、我的拍板（有疑问处，按最有利于我的方向定）

1. **「删除」删的是整条子树**（该段 + 其后长出来的全部内容），不做"只删这一段、后面接回上一轮"的花活。理由：树模型下"这一段之后"本就是我一个人的命运，剪枝是最简单的心智模型；接回去要再造一套缝合逻辑，不值。
2. **删除不做撤销，我接受**。但确认弹窗必须给出量级（**将删除 N 轮 / M 个节点**），光说"以及它后面长出来的所有内容"太抽象，我没法判断代价。
3. **删除后留在路线视图**，我认同（树上少一张卡就是反馈，比切回舞台更符合"我在整理分支"的心境）。
4. **不做备忘表、只留 `prevLeafId`**：方向的克制我认，够用；但按 M1/M3 收紧，别让我为"省一张表"付出"删完枝后行为不可预期"的代价。
5. **「回到选项」删除**：批准（我点名要的三动词）。同时我确认**跳转 = 回到该段开头**是唯一入口，接受它比"回到选项"慢。
6. **`lineage.jsonl` 只增不改、删除只落 `session.json`**：这个取舍我认，但要在 troubleshooting 或计划里写明已知边界——**若将来需要从 `lineage.jsonl` 重建，已删内容会复活**。不要留一个日后谁都不知道的雷。
7. **舞台「重来」改名「重写」**：批准，能力不变（`StageTheater.tsx:646-656` 文案与 `title` 一并改）。

## 六、过度设计检查

**没有过度设计。** 三处新增原语（`childrenOf` / `beatEndFrom` / `removeSubtree`）都是复用与删除的必需品；`recordFork(origin)` 是为来源标签服务的；`LineageOps` 从 `jump/fork` 收敛成 `jump/rewrite/remove` 是把我点的三个动词落到代码面上，不是加料。明确否掉的四件事（备忘表、删除撤销、动既有原语、改切轮规则）我全部同意。这一节写得好。

唯一要盯的是 M5：把选中做成"标记"是**做小了**，不是做多了——别用"克制"给半成品背书。

## 七、改完我怎么验（验收口径）

1. 演到第二轮末尾 → 点卡片「跳转」→ 选**同一个**选项：**没有模型调用**、没有新节点长在当前挂载点下、末梢就是旧那拍的 `beat_end`；
2. 同上场景改选**另一个**选项 → 长出新枝，新枝与旧枝都是"已去过"状态；
3. 在 A 枝玩过 → 重写这条枝 → 回到同一锚点选同选项：**走重写那条**（这是我说"最后去过优先"的原始场景）；
4. 删掉一条枝 → 树上不留空壳、再回去选同选项不炸（M1）；
5. 点卡片可选中，且选中时**看得出这条枝通到哪、删掉会没掉多少**（M5）；
6. 卡片上只有三个动词，删除有确认弹窗且写了数量，跳转/重写的提示文案一眼能分出"生不生成"（M6）；
7. 舞台导演栏按钮已叫「重写」，能力与之前一致。

前 4 条不过，就是②没修好；第 5 条不过，就是③没接住。
