## 玩家的原话

- 已修好：「分支接点」。
- **没修好**：「回到选项/从头重读，通过这俩回去之后，除非选了不同选项，否则应该走同样的剧情而不是自动创建新 branch。现在还是永远到了下一 beat 就开始重写。（这可以类似于某种缓存……但也要考虑到可能同一个选项也可能有两条分支（比如用户在一条枝上重写了），那就要选用最后去过的那条枝）」

## 一、回到旧轮之后走原路

### 病根

`playerAction` 只认「玩家做了一次动作」这个事实，从不回头看树：动作一到就 `deliverPrompts` → `beginBeat`，于是**总是新生成一拍**，并在当前挂载点下多长出一条新枝。玩家在旧轮末尾重选同一个选项，本该是「接着上次那条枝读下去」。

### 规则（一条，落在唯一一处）

**动作要对齐旧路时，先查树上有没有现成的下一拍；有就走进去，没有才生成。**

判定收在 `playerAction` 生成之前（开场那一轮与排队 steer 的路径不经过它）：

1. 只在**轮边界**上认旧路：当前挂载点（`tree.leafId`）的 kind 必须是 `beat_end`。轮中被锚定（`jump` 到某一句话、轮内分岔留下的 pause 出口）时不认——那时 `leafId` 的子节点是**本轮的下一句**，认了会把「继续」接回自己这一轮的后半截。
2. 本次动作的来源标签 `key`：
   - 选项 `i` → `input:（选择了：<options[i].text>）`（与落谱系那条 prompt 的 `input` 同字面）；
   - 自由输入 → `input:<原文>`；
   - 继续 → `continue`。
3. 候选 = `leafId` 的子节点里来源标签相同的那些。**来源标签**（`originOfBeat`）：
   - `prompt` 节点 → `input:` + `payload.input`（本来就是它）；
   - `fork` 节点 → `payload.origin`（见下，重写继承被顶掉那一拍的来源）；没有则 `continue`；
   - 其余（`say`/`narrate`/`scene`/…） → `continue`（「继续」不落 prompt 节点，这就是它的身份）。
4. **候选必须是「有内容的一拍」**：`beatEndFrom(候选)` 解得出来才参选。空壳 fork 标记（子树被剪光的重写枝）一律不参选——它不是一拍，走进去是死胡同。
5. 候选里挑**最后去过的那条枝**：优先挑子树里含 `prevLeafId` 的那条；都不含就挑**子树里 `createdAt` 最新**的一条（「这条路最近还被人走过」比「这条路先长出来」更接近玩家的直觉）。
6. 命中 → **不生成**，把世界线接进那条枝（下节）；未命中 → 走原来的生成路径，一个字节不变。

队列里压着待注入的引导（插一句）时**不认旧路**：玩家排了话就是要新的走向，直接生成（与今天一致）。

### `prevLeafId` —— 「最后去过的那条枝」的依据

它的字面定义是：**上一次显式结构操作（`jumpTo` / `forkTo` / `deleteBranch`）发生之前，世界线所在的那个节点**。之所以够用，前提是「想回到旧轮就必先做一次结构操作」——回到旧轮的唯一入口就是跳转，所以那个位置就是「我这次回来之前在哪儿」。

生命周期（M3）：

- **写入**：只在上面三个动词**进入时**记一次（`forkTo` 里要在改写它之前先把值读出来用于继承来源）；`rebuildBranchAt` 里**不写**——判废回滚、逐拍走路都不是玩家的结构操作，写了会把「上次走过的路」冲掉。
- **删除时**：被删子树若含 `prevLeafId`，删完它就成了悬空引用——回落到「删除之后世界线所在的那个节点」（即被删段的父节点，或世界线本来就不在这条枝上时原样保留）。
- **读档时**：`session.json` 里没有这个字段（旧档），或它指向的节点已不存在 → 一律按「无偏好」处理（当它是 `null`），不得当成命中。

### 接进旧枝：**一次接一拍**

命中的候选节点 `head` 就是下一拍的首节点，接进去 = 世界线挂到**这一拍的末节点**、播放头钉在这一拍的开头：

```
const endId = tree.beatEndFrom(head);              // 沿唯一子节点走到本轮结束（见 core）
await this.rebaseAt(endId, "顺着原路继续", { mark: false, playFrom: "start" });
```

- `mark: false` → `tree.jumpTo`，不落 fork 标记：走老路不是分岔。
- `playFrom: "start"` 是现成的语义：「最后一个 beat_end 之后的那一段」正是这一拍，播放头落在它第一句上，客户端从头演一遍。
- 一拍拍接（而不是一口气跳到这条枝的末梢）：**轮与轮之间的停止点重新摆出来**，玩家可以在任何一拍改选别的选项就地分岔 —— 这正是「除非选了不同选项」。跨轮的那些停止点因此不会被跳过。

### core 新增的小口子

- `LineageTree.childrenOf(nodeId): LineageEvent[]`（现在只有外部各处自己建索引）。
- `LineageTree.beatEndFrom(headId): string | null`：沿唯一子节点往下走到本轮结束，与 `apps/web/src/stage/beats.ts` 的切轮规则同构。停在三处 + 一处无解（M2）：
  1. 走到 `beat_end` → 返回它；
  2. 唯一子节点是 `fork` 标记（分岔标记属于下一段，不在本轮内）→ 返回当前节点；
  3. 子节点不唯一（轮中被截断）或没有子节点（这一拍就到此为止）→ 返回当前节点；
  4. `headId` 自己是 `fork` 标记、且它的子节点不是恰好一个 → **返回 `null`**（空壳 = 没有内容；多个孩子 = 一个岔口，不是一拍）。这是唯一的无解情形，调用方必须处理；复用规则的候选筛选直接用它当过滤器。
- `recordFork(nodeId, opts?: { origin?: string })` → fork 事件的 `payload.origin`。
- `originOfBeat(event): string`（导出）：上面那张来源标签表的唯一实现。
- `LineageTree.removeSubtree(nodeId): string[]`：删掉 `nodeId` 及其全部后代，返回被删的 id 列表；若当前 `leaf` 在删除集里，把 `leaf` 挪到 `nodeId.parentId`；清掉被删节点的快照与改写旁注；**再顺着父节点上溯，把因此变成空壳的 `fork` 标记一并删掉**（M1：fork 标记是卡片首节点的父、不进 `card.nodes`，只删 `nodes[0]` 会留下一个带来源标签的空节点，下次复用正好命中它）。

### 重写要继承被顶掉那一拍的来源

新枝的来源标签必须与被顶掉的那一拍一致——否则玩家回到同一锚点重选同一个选项时，认不出「这条就是刚才重写出来的那条」。

锚点 `nodeId`（= 卡片首节点的父）之下、原来那一拍的首节点，就是要继承来源的那个节点。取法（按优先级）：

1. **客户端点名**（路线卡片走这条，最准）：`fork` 消息带 `replaced` = 这张卡的首节点（`card.nodes[0].id`，它的 `parentId` 恒等于卡片的 `forkFromId`），服务端直接取 `originOfBeat(replaced)`。
2. **世界线在锚点之下**：`tree.leafId` 是 `nodeId` 的后代 → 取路径上 `nodeId` 的那个孩子（舞台导演栏的「重写」走这条）。
3. 都不成立 → 不写 `origin`（读成 `continue`）。

### 于是玩家的场景成立

- 演到第 4 轮，跳回第 3 轮末尾，重选**同一个**选项 → 命中旧枝，`beatEndFrom` 走到原来第 4 轮的 `beat_end`，从头重读，**不调模型**。
- 改选**另一个**选项 → 没有同来源的候选 → 照旧生成新枝。
- 在旧枝上重写过第 4 轮 → 锚点下同来源的候选有两条，`prevLeafId` 指出「刚玩的是重写那条」→ 走重写那条。

## 二、动词三改

| 卡片动词 | 现在的实现 | 改成 |
| --- | --- | --- |
| 回到选项 | `jump(endNodeId, {playFrom:"end"})` | **删除**。这是一次取舍，不是「重叠」：省掉的是「秒到选项」，换来的是三动词的极简；它成立的前提正是本轮第一条把「同选项走原路」修好了。 |
| 从头重读 | `jump(endNodeId, {playFrom:"start"})` | 改名 **跳转**（回到这一段开头，从头演一遍），行为不变 |
| 重演本轮 | `fork(forkFromId, {resume:true})` | 改名 **重写**，并支持一句指令（见下） |
| —— | —— | 新增 **删除**：剪掉这一段及它之后长出来的全部内容，带确认弹窗 |

三个动词的语义要写死在 `title` 里（M6）——卡面只此一处解释：

| 动词 | title |
| --- | --- |
| 跳转 | 「跳转：回到这一段的开头，从头演一遍。不重新生成，选项照旧。」 |
| 重写 | 「重写：退到这一段之前，让剧作家重新写一遍这一段（原有内容留作旧枝）。可以交代一句要求。」 |
| 删除 | 「删除：剪掉这一段，以及它之后长出来的全部内容。会先让你确认。」 |

- `LineageOps` 收敛成 `jump(nodeId, {playFrom})` / `rewrite(forkFromId, instruction?)` / `remove(nodeId)`；`fork` 不再从卡面暴露，重写的组合收在 `rewrite` 里，卡面只管动词。
- 舞台导演栏的「重来」按钮文案与 title 一律改「重写」（`StageTheater.tsx`），能力不变。

### 重写的指令输入（M4）

点卡片「重写」→ 复用 `ui/Modal.tsx` 弹输入框（与舞台导演栏同一手感），**允许留空 = 纯重写**，填了 = 带一句交代。

指令的**实际时序与舞台完全一致**，计划如实写：先 `fork(forkFromId, {resume:true})` 让新的一拍开跑，再把指令排队（`prompt`）。因此那句话生效于**重写之后的下一次开口**（下一轮，或与玩家的下一次选择合并），**不是**写进正在重写的那一轮。卡片上的措辞照此写：「重写这一段，并交代一句」，不写成「立刻改写这一轮」。

### 删除（后端新原语）

- 协议：`ClientMessage` 加 `{ type: "delete_branch"; nodeId: string }`，`nodeId` = 这一段的首节点（`card.nodes[0].id`）。
- 编排器 `deleteBranch(nodeId)`：
  - `guardIdle()`（正在演的那一轮不能剪）。
  - 节点不存在 → 报错；`nodeId` 的父为空（开场那一轮）→ 报错「开场那一轮不能删」。
  - 记 `prevLeafId`（结构操作）→ `removeSubtree(nodeId)`（含空壳 fork 清理）→ 悬空回落。
  - 把世界线重挂到删除后 `tree.leafId` 所在处并 `rebaseAt(leafId, "剪掉这一段", { mark:false })`：缓冲、引擎状态、客户端整段重建，选项重新摆出来，玩家就地重选。世界线本来就不在这条被删的枝上时，`leafId` 没变，重建是幂等的——玩家的位置不被这一剪拽走。删除波及阅读位置时，`rebuildBranchAt` 里现成的 readPos 校正会把它归零到新落点。
  - `rebase` 消息带 `keepView: true`：删除是「在路线里整理分支」的动作，客户端不要切回舞台。
  - `lineage.jsonl` 是只增不改的审计流，读档只读 `session.json`（`store.loadSession`），因此删除是持久的。**已知边界**：若将来改成从 `lineage.jsonl` 重建，已删内容会复活——写进文档。
- 确认弹窗在 `RouteCanvas` 里（复用 `ui/Modal.tsx`）：文案说清后果，并给出量级「将删除 N 轮 / M 个节点」（N = 该卡及其后代卡片数，M = 这些卡片覆盖的谱系节点数），确认键用危险色。删除后**留在路线视图**（树上少一张卡就是反馈）。

## 三、路线视图看得清 + 能选中

### 连线（M5 的前提）

- `.route-edge`：底宽 1.5 → 2、live 2 → 2.75、`stroke-linecap: round`；废弃枝 `opacity .5 → .72`、虚线疏一点；fork 支线换个更实的描边（`--accent` 半透明 + 宽 2）。
- `route-dot` **已经在用**（给 on-path 卡片画端点圆点，位置本来就落在连线的子节点端），本轮的改动只是随加粗把半径调大一档、并描一圈卡底色，让它从卡片边缘读得出是个「接头」。

### 选中（M5）

点卡片即选中。选中不是描个边就完事，它要回答「这条枝通到哪、删掉会没掉多少」：

- **选中卡**：`.route-node.selected`——accent 描边 + 外发光环 + 抬 `z-index`（抬了之后卡内动词按钮照旧可点，动词行 `stopPropagation` 不把点击当成选中）。
- **祖先链**：`.route-node.kin` 淡描边，连同这一段的来路一起高亮（`.route-edge.kin`）。
- **该段及其全部后代**（= 删除会波及的范围）：`.route-node.doomed` 用危险色虚线描边标出（`.route-edge.doomed` 同步）。同一次子树遍历算出来，几乎白送，却把「删除删的到底是哪一段」在动手之前就摆到眼前。
- 三态样式与既有 `live` / `here` / `dead` 分层：`live` 只染左边框、`here` 是 accent 实描边、`kin` 是淡描边、`doomed` 是危险色虚线、`selected` 是 accent 描边 + 外环——互不覆盖同一属性。
- 点画布空白或按 `Esc` 取消。

## 四、不做什么

- 不引入「按 (锚点, 选项) 记时间戳的路线备忘表」：一条 `prevLeafId` 就够覆盖用户说的场景，多一份随分支增长的持久状态不值。
- 不给删除做撤销：谱系是 append-only 的审计流，撤销要再引入一层墓碑，收益不抵复杂度；确认弹窗把后果与量级说清楚。
- 不动「插一句」「编辑台词」「轮内分岔」「腰斩」这些既有原语，不改切轮规则。

## 五、测试计划

- `packages/core`：`childrenOf` / `beatEndFrom`（beat_end、fork 截断、多子截断、尾节点、**空壳 fork 返回 null**）/ `removeSubtree`（连根删、删中间枝、leaf 落在删除集里回落父节点、快照与旁注清理、**删完把空壳 fork 标记一并清掉**、**空壳 fork 的上溯链**）/ `recordFork` 带 origin / `originOfBeat` 三种节点。
- `apps/server`（`test/orchestrator.test.ts`）：
  - 同选项回到旧轮 → **不调用模型**、世界线接进旧枝、末梢是那一拍的 `beat_end`；改选另一个选项 → 生成新枝；
  - 重写之后同选项 → 走重写那条枝（`replaced` 与 leafId 两条取来源的路径各一例）；
  - `prevLeafId`：先跳走再回来选同选项走最近那条；旧档缺字段 / 指向已删节点按无偏好处理；
  - 候选是空壳 fork（子树被剪光）→ 不参选，照常生成；
  - 轮中锚点上「继续」不认旧路（仍生成）；
  - 删除 → 节点与后代消失、空壳 fork 不残留、世界线回到父节点、开场那一轮报错、删别的枝不动世界线。
- `apps/web`：`beats.test.ts` 不动（切轮规则没改）；`RouteCanvas` 上补一例（三个动词渲染 + 删除确认弹窗写出量级 + 点卡片选中给出 kin/doomed）。
- **端到端**（`e2e-tester`，验收命门）：演两轮 → 跳回第一轮 → 选同一选项 → 确认没有模型调用、末梢是旧枝的 `beat_end` → 改选别的 → 确认新枝长出来。
- 受影响的既有用例先跑：`apps/server/test/orchestrator.test.ts`、`apps/web/src/stage/`、`packages/core`。
