## 结论

准入。三个包的 typecheck、测试、构建全绿，四个导演动词在浏览器上逐个验过。
留了一条已知遗留（「重来」之后舞台要点一下才显示新内容），不阻塞合入。

## 设计上值得记的三点

**1. fork 降级是对的。** 原来「分岔」这个按钮自己就带重新生成，语义是两件事捆在一起。
拆开之后分岔只做一件事（挂载点移过去 + 落一条标记），重新生成交给「重来这一幕」这个
组合。用户想「换个方向接着演」和「回到那条线看看」是两个不同的诉求，捆在一起会让第二个
诉求没法表达。

**2. 锚点必须是拍首。** 原来 `recordRewrite` 的锚点是 `target.parentId`，也就是分岔到目标
的**前一个**。这会重演到玩家上一次表态之前，等于把玩家刚做的选择又问一遍。改成锚拍首
之后，上一次选择作为链尾悬空的输入并进新拍，玩家看到的是「从我这句之后重来」。

**3. 编辑是旁注不是重写。** 「编辑消息就是纯原地，不要创造隐藏分支」——这条决定了
`recordEdit` 的 `parentId` 是 null，它不占树上的位置，物化时覆盖目标行文字即可。副作用是
`materialize` 的重放链上找不到编辑事件，编辑只能靠 `this.edits` 这张旁注表回填。

## rebase 的 15 个冲突

`git rebase main` 时 `main` 那边也在改同一片区域（`909a9fb` 删检视栏、`7a4e8d7` 节点样式改回
旧观感、`1a72f10` 跳转/分岔正名）。逐个处理时的判断：

- **主线的「每卡两个动词按钮」布局保留**——那是 `7a4e8d7` 特意做的，不是误改。
- **主线的 `recordRewrite` 换成本分支的 `recordFork`**：主线 UI 上按钮标着「分岔」图标是
  `fork`，方法却叫 `recordRewrite`，名实不符；而且它的锚点会重问玩家上一次的选择，
  正好踩中第 2 点。
- **`editInPlace` 合并进 `recordEdit`**：两个方法做的是同一件事。
- **`rebuild.ts` 取主线的薄适配层**（`coreLineageToEvents(chain.map(toNodeView))`），
  本分支那份重复的 `editOverrides` 拷贝是死代码。
- **`routeTree.ts` / `RouteCanvas.tsx` 取主线结构 + 本分支的 `⑂` 角标**。
- **`LineagePanel.tsx` 取主线的 `RouteCanvas` 调用形状**，删掉本分支带检视栏时代留下的
  `rewindTargets` / `BeatActions`（它们引用了已经删掉的 `beatAnchors`，留着过不了 tsc）。
- **`StageTheater.tsx` 全取本分支**（11 个块）：三按钮导演栏取代常驻导演注浮层是这次需求的
  核心变更。
