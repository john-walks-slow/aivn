# 用户验证要求：停止点回到 DSL（`<stop …/>`）

日期：2026-10-06

改动本身（解析器 + 插件内部）已由自动化覆盖；下面两条是**只有真人点得出来**的东西：
DSH 原生分支键的可用性，以及它在你自己那台机器上的观感。

现成实例（改动的库已加载，勿用它做别的）。端口是 `acquire-port` 动态发的，**每次重启都会变**，
所以地址现取：

```bash
cd ~/projects/dsh-aivn && dsh-e2e status      # 打印当前 http://127.0.0.1:<port>/?token=e2etest
```

## 场景

1. **拍尾的分支键不再置灰**（本次改动的目的）
   开一条剧作家会话，发一句话让第一拍演完；切回 **Chat**，鼠标移到刚演完那一轮的最后一条消息上，
   点「在新对话中分支」。**看什么**：这个键这次是**可点的**（改动前它恒为灰、提示「仅可从已完成轮次的
   最后一条消息分支」）；点完真的开出一条新会话，切到它的 AIVN tab，画面停在同一个点、停止点选项也在。

2. **停止点仍然照常**
   在 AIVN tab 里点一条选项 → 台词继续演；演到拍尾再出现选项面板（或自由输入框）。
   **看什么**：选项面板的出现时机与内容跟以前一样，没有多出「继续」卡、也没有半个标签被念上台。

3. （顺手看一眼）**自然收尾**
   对剧作家说一句「这一拍自然收尾，不给选项」，或让它写 `<stop/>`。**看什么**：舞台上是普通的
   「继续」卡，不是选项面板——这一条与改动前 `beat_done()` 空参数的行为一致。

## 说明

- 停止点的写法变了（`<stop options="甲 | 乙"/>` / `<stop placeholder="…"/>` / `<stop/>`），但这只在
  你看会话原文或自己写剧本时才看得见；README 的「Agent 工具」一节已同步。
- 自动化证据（含分支键 `usable: 3`、子会话 107 帧重建、三拍日志尾部原文）见同目录
  `261006-aivn-stop-tag.e2e.md`。

## 验收结论（2026-10-06）

三条场景在**独立 worktree（钉在 `2798292`）+ 隔离实例**里实跑通过，证据见同目录
`261006-aivn-stop-tag.acceptance.md`（三张实拍图已随报告入库）：

1. **分支键可点**：`aria-label="Branch into a new conversation"`、`aria-disabled = null`、
   `disabled = false`；点下去真的开出子会话，新会话的 AIVN tab 停在同一个演出位置、选项面板完整继承。
2. **停止态可辨识**：一拍演完停在可辨识的「已停止」终态（选项面板 / 普通「继续」卡），不是消失。
3. **自然收尾不与 2 混淆**：模型写裸 `<stop/>` 时是普通「继续」卡，且标签没有泄漏到台词里。

第二条里那句「选项原文回到剧作家、时间线多一行回执」是舞台**既有的**玩家动作处理
（`player_input` 帧，2026-10-04 `8298113c` 引入），不是本次改动新增的界面层——验收口径因此只要求
「一眼看出一拍已经停在可辨识的终点」，不额外要求任何新 UI。

验收口径只做界面级确认；图里的 DOM 读数水印是机器可读的那份证据，未另做肉眼像素复核。
