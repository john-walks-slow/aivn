# 检视报告

## 概要

检视范围涵盖 `@aivn/core`（`packages/core`）的 `<stop>` 标签语法恢复与解析实现、测试用例更新，以及 `dsh-aivn` 插件中移除 `beat_done` 工具和 `beat-guard`、适配新标签提示词与上下文注释的完整改动。
整体评价：方案准确击中了 DSH 原生「在新对话中分支」依赖助手消息轮尾的核心痛点，同时顺带彻底修复了 `stage-log` 历史重投影中工具产物丢失的既有缺陷。整体设计轻量自然，代码干净无冗余，向后兼容考虑周全，准入结论为**准入**。

## 需求对齐

变更完全满足计划文档（`261006-aivn-stop-tag.plan.md`）要求：
1. **停止点移回 DSL**：`<stop options="… | …"/>`、`<stop placeholder="…"/>`、`<stop/>` 三种形态在 `StageDslParser` 中实现，`options` 解析逻辑与旧 `beat_done` 严密对齐。
2. **分支判据与历史重投影修复**：轮尾恢复为 `assistant/message`，使得 DSH 会话分支键恢复可用；且在 `stage-log` 重投影助手文本时，停止点能被同一解析器自然还原。
3. **架构简化**：删除了 `beat_done` 工具定义和 `beat-guard` 追收束机制，清除了 `hasLines`、`beatClosed` 等一系列穿透性状态维护。
4. **与计划偏离**：无偏离。

## 针对重点考量问题的专项分析

### 1. 删掉 `beat-guard` 是否留下了未被覆盖的退化？
- **分析**：
  - `beat-guard` 原本的作用是在 `agent/turn-stopping` 捕获「模型写完了台词，但忘了调用 `beat_done` 工具（或者错误地把 `beat_done` 写成了正文标签）」的场景，并通过 `steer` 追加一步追问。
  - 在改用 `<stop>` 标签后：
    1. 最常见的失败模式（快模型直接把收束写进正文）从原先的「错误写法导致工具未调用」变成了「正文原生正确写法」，模型直觉更契合 Markdown/DSL 流式输出。
    2. 若模型完全没有写 `<stop>` 标签：在文本层面上，「模型写完自然停笔」与「模型打算继续」在不靠工具显式声明的情况下是无法区分的。强行探测台词去追问，会导致原本合法的「自然演完」每一轮都被多罚一次 LLM step，得不偿失。
    3. 在消费端，`stage-view.tsx` 前端当没有收到 `stop` IR 事件时，`stopAffordance` 会 fallback 到 `no_stop` 状态，玩家界面呈现常规的「继续」推进卡片，客户端已有完善且自洽的兜底通路。
- **结论**：删除 `beat-guard` 是利大于弊的架构减负，没有留下未覆盖的致命退化。

### 2. `<stop>` 的坏载荷处理取舍（挂解析警告 vs 工具错误回执）
- **分析**：
  - 在原工具方案中，参数不合法（如 `options` 只有 1 项）可以 throw Error 并给模型一个工具错误回执促使其单步重试，但这也消耗了额外的 LLM 轮次和时间。
  - 在标签方案中，DSL 标签是一次性由助手流式生成的，解析器采用容错设计：
    - `options` 不足 2 条时丢弃该属性并挂 `malformed_tag` 告警；若有 `placeholder` 则退化为自由输入框，否则视为自然演完（`no_stop`）。
    - `options` 与 `placeholder` 同时给出时优先 `options`，并记录 warning。
  - 这种设计符合 Stage DSL 容错规范（如属性解析错误、未闭合标签自闭合等统一挂 warning 不中断演出），且前端有「继续」兜底，体验平滑，取舍完全合理。

### 3. `options` 用 `|` 分隔及双引号转义的协议风险
- **分析**：
  - 短句选项在中文/英文语境下自然包含竖线 `|` 的概率极低，且选项本身应简洁有力。
  - 提示词中已明确约束：「选项里不要出现 `|` 与英文双引号（要引用别人的话就用「」）」，在源头做了规范引导。
  - 属性解析器 `parseAttrs` 已经按双引号提取属性值，只要提示词约束了不要在属性内部写未转义的双引号，`options="..."` 的解析即极其健壮。
