## 场景 1：同一场景里三个主体的头顶是否齐平

- 修后：三个头顶落在同一条线上，人物高度都等于声明的体量档。

判据（像素值，可自行量）：桌面三个头顶应分别在 162 上下，窄屏在 135 上下。

## 场景 2：窄屏的横向拥挤度（需要你裁决）

立绘的渲染宽度 = 盒高 × 画布比。portrait 列的 `full/normal` 是 102% 舞台高，
所以「人物内容占满画布宽」的主体（测试里的机器人 chusan）渲染宽度约 57% 舞台高——
在 390 宽的舞台上，**修前就已经超出屏幕**（484px > 390px），修后放大到 575px，更明显。

这不是补偿引入的，是那一列的高度本身偏大。两种收法（都在 `packages/core/src/play/spriteStage.ts`
的预设表上，不动组件的落位公式）：

1. portrait 列整体降档（normal 从 102% 降到 ~80%），代价是所有人变小；
2. 只给「宽主体」限高——需要在表里按画布占比分两列，改动大一些。

维持现状也成立：人物大小是预设想表达的意思，宽主体溢出是它自己的比例。
