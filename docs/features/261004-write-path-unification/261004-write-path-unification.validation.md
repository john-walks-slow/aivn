# 工坊写路径统一 · 用户验证要求

改动落在「剧目文件被改动 → runtime 重建」这一条链上，验证面分四组。
需要真实交互的只有 B 组（要开一个剧目、点保存）。

前置：在 `.worktrees/workshop-shell` 里起服务
（`./scripts/init-worktree.sh` 之后 `./scripts/dev-worktree.sh`，端口现取），
浏览器打开输出的地址，选一个剧目进工坊。

## A 组：文件页写坏 play.json 会被拦下（本次核心）

1. 工坊 →「文件」页 → 选中根层 `play.json`。
2. 把内容改成不合法的 JSON（例如删掉最后一个 `}`），点保存。
3. 期望：**报错**，提示里含「play.json 结构校验不过，未落盘」与具体原因；再点进 `play.json`，
   盘上还是刚才那份好的（不是被改坏的那份）。
4. 把它改成合法 JSON 但删掉 `"title"` 一行，保存 → 同样被拒，提示「缺少必填字段（id/title）」。
5. 改回完全正确的内容，保存 → 成功，且**舞台立刻按新配置生效**（不用重开剧目）。

## B 组：正常改动照旧「保存即生效」

1. 文件页改一张记忆卡（`memory/**` 下任意 `.md`）保存 → 立即生效，与改动前手感一致。
2. 打开工坊对话，让搭台助手改一个文件（例如「把 premise 里那句时间改到傍晚」）。
   一轮结束后剧目按新内容重建——**一次**（不是中途闪两次）。
3. 在搭台助手正在回复的过程中，去文件页改一张记忆卡保存 → 不被卡住，**立即就地生效**，
   且助手本轮回复结束时不会再重复重建一次演出。

## C 组：bash 那条没校验的路仍然兜得住

> 需要先在该剧目的「Agent」页把搭台助手的「命令行」工具勾上。

1. 让搭台助手执行一条会写坏 play.json 的命令（例如把 `play.json` 覆盖成 `{ broken`）。
2. 期望：对话流里出现一条错误，含「play.json 现在解析不了，已跳过这次的运行时重建」，
   并且**面板没有变成不刷新**；按提示去文件页修好（此时会走 A 组的校验）后，剧目恢复正常。

## D 组：回归（写路径的其它用户）

1. 素材页「从资源库导入」一个带 role 的主角卡条目 → 导入成功，剧目主角卡已更新。
2. 让搭台助手出一张图 → 图正常落盘、素材页可见、撤销条正常。
3. 工坊「设定与记忆」页改创作口径（`craft.md`）保存 → 立即生效。
