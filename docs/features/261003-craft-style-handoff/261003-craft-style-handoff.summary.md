# 创作口径外置到 craft.md + 工坊提示词可配

日期：2026-10-03
分支：`feat/craft-style`

## 起因

工坊 Agent 页原本只有模型 / 思考档位 / 工具开关三项可调，于是有了「把这些工作风格抽成参数」的想法。构思到一半改主意：不参数化，改成**引擎不再自带任何创作口径**，全部由剧目的 `memory/always/craft.md` 承载。

## 四项改动

### 1. 生图「提前 3–5 句」彻底删除

散在 `prompt.ts` 三处与 `agentkit/imageTool.ts` 三处（含工具描述与两处回执）。

**为什么它是错的**：舞台是流式的，模型边写边播（`stage/script.ts` 把 `text_delta` 增量 append 到当前行）。一句中文台词出 token 约 0.5–1 秒，「3–5 句」满打满算只给图 3–5 秒的头，而实测出图要 70–110 秒——差二十倍。这个数不是推导出来的，是拍脑袋的经验值。

**删掉后留什么**：只留事实，不再留策略。工具描述里写「图到货要一分多钟；这一轮就引用到它，舞台会先上骨架占位，台词照常演、到货后自动淡入」。骨架占位 + TTL 上界本来就是引擎的正常降级路径（`stage/director.ts`），不是错误状态。

### 2. 创作口径从系统提示词撤到 craft.md

删除的东西：

- `prompt.ts` 导出的常量 `CRAFT_RULES`（一轮 10~25 句 / 500~1500 字、展示而非陈述、保持剧情推进、好感度自然体现）
- 「# 单轮该写多长（硬要求：默认写长）」整节
- 演出契约第 6 条（何时给停止点）、第 7 条（一轮至少 10 句 / 500 字）
- 「你怎么工作」与「结束轮」里的选项数量（2~4）
- `beatTool.ts` 描述里的策略句「选项要在主角必须表态的那一刻给…」

保留下来的：**引擎事实与契约**。DSL 格式、`beat_done` 三种参数语义、配乐缺省保持、指令先于台词。

`beat_done` 的 schema 仍留 `minItems: 2`——那是无效载荷护栏（一条选项的面板没有意义），不是风格；`maxItems` 4 → 8，只防模型一次甩二十条撑爆面板。

**代价（知情接受）**：craft.md 空着，剧作家就真的没有任何口径。工坊「设定流程」第 4 步因此改成硬性要求落盘，剧目写作要点里也把 craft.md 那一条扩写成「唯一听这一份」+ 至少写清四件事（每轮多长 / 选项给几条 / 交还主导权的密度 / 文风与禁忌）。新建剧目时它默认是空文件——**没有加就绪门**，用户认为那是过度防御。

### 3. `<comment>` 降级

格式章保留定义（模型得知道有这个出口，否则「不聊天」这条要求就没地方落地），但正文只剩一句事实：不上舞台、不进谱系、不产出事件。

删掉的两处邀请：格式章的「记录打算、提醒自己后面要收的伏笔、把想说的先写下来」、演出契约的「想写这类内容就放进 `<comment>`」。

现在整个提示词里 `<comment>` 只出现一次（格式章那一次配平的示范）。

### 4. 工坊 Agent 可配置提示词

`play.json` 的 `agents.workshop.prompt`（`AgentSettings.prompt`）存一段自由文本，原样追加到工坊系统提示词**末尾**，标题「# 本剧目的补充要求」。Agent 页只有搭台助手那张卡有对应输入框。

放末尾而不是放开头：固定段讲引擎契约与能力边界，自定义段讲这个剧目额外的做事要求，冲突时后者才是用户的本意。

取自当轮现读的 `play.json`（`workshopSession.systemPrompt()` 每轮 `loadPlay()`），不吃构造快照——用户改完立刻发下一条消息就生效，不用等 runtime 重建。模型与工具开关仍走构造期的 `opts.agents`，那条路要重建 runtime。

- `pnpm -r typecheck`：core / server / web 全部通过
- `apps/server/test/{prompt,workshop,agentkit}.test.ts`：81 例通过（含新增的「引擎不再自带口径」「四个维度」「自定义段追加/空值无痕迹」）
- `packages/core`：116 例通过
- `apps/server` 全量：428 例里 1 例失败（`playAssets.test.ts` 临时角色 stub），来自本 worktree 从 main 同步过来的在途改动，与本次需求无关

未做实机验证：改完请在工坊「Agent」页写一段补充要求发一轮对话，确认它生效；再开一部新剧目走设定流程，确认 craft.md 被写出来。

## 遗留

- craft.md 为空时的裸奔状态没有兜底（就绪门不卡 craft）。若实机发现剧作家在空 craft 下写得太短或太长，第一反应应该是把 craft.md 的落盘做得更硬，而不是在引擎侧把默认加回来。
- `prompt.ts` 仍留「一轮是完整的小场面」这类结构性描述（不含量化口径），是有意为之：一轮 = 一个 beat 是引擎语义，不是风格。
