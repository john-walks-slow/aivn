# 检视报告

## 概要

本轮检视针对 `261004-sprite-variants` 特性全量修改，涵盖 `packages/core` 差分词表真相源与辅助函数、`apps/server` AgentKit 工具描述对齐、`apps/web` 批量差分模式（chips 多选、自定义追加、任务进度与回执认领）、身份基准可见性及相应样式。
整体设计遵循「前端扇出、服务端协议与闸门不动」的极简原则，单张流程向下兼容，真机并发出图验证闭环。代码无阻塞性缺陷，但在待生成清单交互、WS 结果广播认领及生成收束态 UX 上存在若干建议改进项。

## 需求对齐

- **差分词表真相源（core）**：`COMMON_SPRITE_VARIANTS` 与 `spriteVariantChoices` 规范导出，单测完备覆盖（4 条通过）；`apps/server` 的 `generate_image` 工具描述复用该词表，模型契约保持单字符串不变。完全满足。
- **身份基准可见性（web）**：`ImageGenDialog` 准确呈现身份基准行，包含缩略图与垫图说明；缺失定妆照时严格对齐服务端两条分支（全空自动补定妆照 vs 已有其他差分报错阻止换脸）。完全满足。
- **批量出图与逐张进度（web）**：素材页新增「+ 差分」批量入口，沿用单张 REST 端点并发提交，按 `target` 逐行认领 WS `image_result` 并渲染成图缩略图或错误原因。完全满足。
- **与计划偏离点**：
  1. 计划文档约定「输入框追加自定义词，重复的忽略；清单可单条删」。实际实现中自定义词未渲染为可删除的 chip 或 tag，仅作为纯文本展示；若用户输错无法单独删除；且输入已存在词时由 `toggleVariant` 处理成了反选移除，而非「重复的忽略」。
  2. 批量生成全部结束后（无论成功或全部失败），主按钮固定变为「完成」直接关闭弹窗，未给失败项重试或继续提交的交互出口。

## 建议修改

| ID | 位置 | 问题 | 建议 |
| --- | ---- | ---- | ---- |
| REV-01 | `apps/web/src/workshop/ImageGenDialog.tsx:125-142` | `ImageResultEvent` 广播监听中，`if (msg.ok) onDone?.();` 位于 `setJobs` 回调之外，且未检查 `msg.target` 是否命中本对话框的任务。当剧目有其他背景/CG 等并发生成广播完成时，即使本批次并未命中（`idx === -1`），也会意外触发父组件 `reload`。 | 增加命中判定，仅当 `msg.target` 确实属于当前 `jobs` 或 `waitingTarget` 且成功时才调用 `onDone?.()`。 |
| REV-02 | `apps/web/src/workshop/ImageGenDialog.tsx:177-185, 409-417` | 自定义差分词交互缺失单条删除能力。通过 `draft` 回车加入的新词未进入 `choices`（因其仅按磁盘现有文件计算），只在 `待生成 N 张` 纯文本中显示，用户输错后无法移除。此外，若重复输入已选词，`addDraft` 会调用 `toggleVariant` 将其反选剔除，不符合计划中「重复的忽略」约定。 | 1. 将 `addDraft` 改为仅在未选时追加，已选则忽略；<br>2. 将「待生成清单」中的每一项渲染为独立可点击移除的小标签/Tag，或将自定义词动态合入 chips 列表以支持点选取消。 |
| REV-03 | `apps/web/src/workshop/ImageGenDialog.tsx:316-325` | 批量生成收束后的交互引导不够清晰。当所有任务结束（`hasPending === false` 且 `started === true`）时，主按钮固定为「完成」（点击即关闭）。若任务全部或部分失败，用户无法直接重试；且下方表单重新恢复交互后主按钮仍为「完成」，行为不符合直觉。 | 当批次结束且存在 `failed` 任务时，主按钮或辅助操作提供「重试失败项」或「重新生成」出口；仅在全部成功或用户确认离开时提供「完成」。 |
