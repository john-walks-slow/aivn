# 立绘原地重抠底（recut_sprite）

## 问题

抠底参数（`strong`/`weak`/`minHole`/`keySmooth`/`edgeBand`）原来挂在 `generate_image` 的调用参数上。这条路只有两个毛病，而且第二个是死结：

1. **模型填不了这个参数**。填它得先看过成图——出图那一刻没人看过图，模型填的必然是默认值，
   等于调了个寂寞，还让人以为抠底是被控过的。
2. **换参数等于重新出图**。`cutout()` 跑完原片就丢了，落在 `assets/` 里的只有抠完的透明 PNG。
   想换一档参数只能再调一次 `generate_image`，而那是**另一张画**：用户刚点头认可的那张会被覆盖，
   还白烧一次配额、等一分多钟。「图本身可以、只是抠图质量不好」这个状态在旧实现里改不了。

## 方案

把「出图」和「调抠底」拆成两个动作，中间隔一份原片。

- **留底**：立绘抠底落盘前，把抠底前那一张原片写到 `plays/<id>/media-cache/sprite-sources/<角色id>/<差分名>.<ext>`。
  `media-cache/` 已被 `.gitignore` 的同名规则覆盖（已实测），换机器后老图没法重抠——这是有意的取舍：
  原片是中间物，不是剧目内容。
- **重抠**：`PlayAssets.recut()` 读那份原片本地重跑一遍 `cutout.ts`，覆盖 `assets/sprites/` 里那张 PNG。
  画面一个像素不变、几秒出结果、不烧配额。
- **工具**：新增 `recut_sprite`（只装给工坊，`group: "image"`），回执照样贴 markdown 图片。
  触发条件写死在描述里：**用户看过成图说抠得不干净时**才用。
- **`generate_image`**：schema 删掉 `cutout`，两个角色都不再有这张牌；工坊侧描述改成指向 `recut_sprite`。

## 决定

- **留底位置**：`media-cache/sprite-sources/`，与 TTS 缓存同级。放 `assets/sprites/` 会被
  `spriteStems()` 当成一个叫 `neutral.src` 的差分，演出与就绪门全乱；进 git 则是每张立绘多背一份原片。
- **没有留底就报错，不退回重新出图**：留底机制之前出的图与用户自己上传的立绘都没有原片。
  退回「重新出图」等于把第 2 个问题原样交给模型——它会偷偷重画，用户点头的那张就没了。
- **抠底失败不落半残图**：`cutout()` 抛错时 `persist()` 还没被调用，原来那张透明 PNG 原封不动。
- **重抠要等同一张图的出图收尾**：一张立绘出图约 100s，留底是出图途中写的，抢在它前面读到的是旧原片。

## 验收

`apps/server/test/playAssets.test.ts` 的「PlayAssets：原地重抠」四条：

- 出图留底；重抠不调后端（后端调用数不变）；默认档重抠逐字节复现出图产物（证明留底就是当初那张）；
  两处都不透明的像素逐位相同（证明画面没动）。
- 换扩展名重新出图后旧留底被清掉（否则 `readSpriteSource` 会一直命中上一张画）。
- 没有留底的老图 / 上传图、以及还没出过的差分，都直接报错，且不退回重新出图。
- 重抠失败时原来那张透明 PNG 逐字节不变。

`workshop.test.ts`：调参原样进抠底层、回执带图片、失败是可读的一句话不是栈；
`generate_image` 的参数里没有 `cutout`。
