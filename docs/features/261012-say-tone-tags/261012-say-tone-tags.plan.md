# 台词语气标记（对玩家隐藏）— 计划（261012）

## 需求

用户原话：**「对话句支持语气标记（对用户隐藏）参考 /fish-audio（用简化版入剧作家提示词。包含常用 tag（包括 nsfw 后续常用的），无需太多复杂描述）」**。

即：剧作家在 `<say>` 台词里直接写 Fish Audio 的语气标记（`[whispering]`、`[sigh]`、`[laughing]`…），
标记**只对配音生效**、不上海报给玩家看；给剧作家的说明要**简化**（一张常用锚点词表 + 几条位置规矩，
不要长篇分类学）。

## 调研结论（决定了设计）

完整报告：[`docs/freeform/261012-fish-audio-emotion-tags.research.md`](../../freeform/261012-fish-audio-emotion-tags.research.md)
（含本机 `s2.1-pro-free` 21 次实测 + 9 次 ASR 回读）。影响设计的六条：

1. **语法是 `[方括号]`**；`(小括号)` 是 S1 旧语法、S2.1 **静默忽略**（还会被当普通文本念出来 ✗）。
2. **`s2.1-pro-free` 与付费的 `s2.1-pro` 是同一个模型**，标记能力一致。
3. **标记是开放域的**：官方明说 *"treat `[bracket]` tags as standard text rather than dedicated control tokens"*，
   GitHub Discussion #1302 也澄清「15,000+ tags」不是可枚举白名单 → **我们给的是「高命中率锚点词」，不是白名单**，
   引擎侧不做词表校验。
4. **位置即语义**：标记从它出现的位置生效，到下一个标记或句末。句首 = 整句；句中 = 从那里开始。
   → 台词中间也要能写（`[gasp]`、`[pause]`），**不能只支持行首**。
5. **标记是放大器不是覆盖器**（Issue #1280 的系统实验）：文本本身语义中性时 `[sad]` 几乎无效；
   描述性标记（`[voice breaking, barely holding it together]`）比裸标签有效。
6. **叠加 ≤2–3 个；不要以标记结尾**（官方原文：后面没有文本时输出不可预测）。

## 设计

### 一句话

**标记就是台词文本的一部分**（`<say id="mio">[whispering] 别出声……</say>`），一路原样流到 TTS；
**只在「给玩家看的文本」那一层剥掉**。不新增 DSL 属性，不动解析器。

### 为什么不把标记在解析期提出来存成 `tone` 属性

- 位置即语义：一提成属性就只剩「整句一个语气」，句中的 `[gasp]` / `[pause]` 全丢；
- 流式会撕裂标记（`[whi` + `sper]`），解析期要做 pending 缓冲，还得给「模型忘了写 `]`」兜底，
  不然那一行永远不吐字；
- 文本进谱系之后是**补生成、改写、翻译、模型上下文**的共同来源，提出来就得在 5 处同步带属性，
  漏一处就是「跳转/分岔之后这个标记没了」。留在文本里，这些路径一处都不用改。

### 落点

| 层 | 改动 |
| --- | --- |
| `packages/core/src/speech/text.ts` | 新增 `stripToneTags(text)`：按形状（`[`…`]`、不含方括号与换行、≤80 字）剥掉；**流式半路未闭合的那一截也一并藏起来**（玩家不该看见 `[whi`）。词表不校验——开放域 |
| 服务端 `voice.ts` | `speakable()` 的「有没有字可读」判据改用**剥掉标记之后**的文本（只有 `[sigh]` 的一行不合成），送 TTS 的仍是原文 |
| 服务端 `translate.ts` | 翻译提示词加一句：行内方括号标记原样保留、位置不变（否则 `voiceLanguage` 那条路会把标记翻掉） |
| 服务端 `orchestrator.ts` | `recentScript()`（生图提示词的「刚才演到的」）剥掉标记，别把标记喂给生图模型 |
| 客户端 `script.ts` | 台词行同时留 `raw`（原文）与 `text`（上屏用，剥过的）；打字机/reveal/标点节奏全部走 `text` |
| 客户端 `transcript.ts` / `scriptFeed.ts` / `beats.ts` | 取自**谱系节点**的那条兜底路径也剥一次（回顾翻旧轮、路线树预览） |
| 客户端改写框 / 工作坊文件页 / 历史原文 | **保留原文**——作者面要能看见与编辑标记；改写的初值给 `raw`，否则一改就把标记吃掉 |
| 提示词 | `packages/agent/src/prompt/stage-dsl.ts` 加一章语气标记（两个宿主共用），`apps/server/src/prompt.ts` 挂进《台词》章；DSH 宿主同步挂 |
| DSL 契约 | **下线 `mood` 属性**：它是个没人消费的死旋钮（不驱动立绘、不驱动配音、界面上已经不显示），留着只会跟语气标记抢「怎么表达情绪」这一个问题 |

### 提示词那一章（简化版）

给剧作家的只有：语法一句话 + 一张常用锚点词表（分四组：情绪 / 嗓音 / 呼吸与反应 / 节奏；含亲密向几个）
+ 四条规矩（放句首管整句、句中只管后半句、一行最多两个、别放行尾；台词本身要有情绪，标记是放大器；
不要用圆括号；标记不占字幕）。正文由 `expert` 子代理从零写，主 agent 只负责接线。

## 用户路径

1. 剧作家写 `<say id="mio">[whispering] 别出声，他在隔壁。</say>` → 服务端把整句（含标记）送 Fish →
   玩家屏幕上只看到「别出声，他在隔壁。」（打字机逐字、标点节奏都按剥过的文本算）。
2. 玩家点重听 / 补生成：走的是谱系里的**原文**，标记还在 → 补出来的仍是耳语。
3. 导演在回顾里改写这一行：初值带标记（作者看得见），改完仍带标记 → 语音照新文本重合成、语声照旧带标记。
4. 工作坊看剧本文件：标记原样可见（那是作者的稿子）。
5. 模型下一轮的上下文：`lineageToBeats` 写回的是原文 → 剧作家看得见自己上一轮怎么标的（约定自洽）。

## 验收

- 单测：`stripToneTags`（完整/多个/未闭合/中文/非标记方括号/无标记原样）；服务端「标记进 TTS 文本、
  标记-only 行不合成」；客户端「上屏文本剥掉、`raw` 保留、reveal 长度按剥过的算」。
- 真机：假模型网关写一行带 `[whispering]` 的台词 → 真 Fish 合成 → 断言送到 TTS 的文本含标记、
  客户端拿到的文本不含标记；顺手把这一行合出来的音频交给用户听（音色/语气好不好由他判断）。
- 提示词契约：`pnpm check:agent-contract`。

## 遗留 / 不做

- 引擎不校验标记词表（开放域，官方无白名单），也不统计「这个标记到底有没有生效」——
  效果本身不稳定（社区 issue 一堆），靠音色选择与台词语义，提示词里会写清。
- 只对 `<say>` 配音：`<narrate>` / `<thought>` / `<title>` 不配音，写标记没意义（提示词里会说明；
  上屏侧照样剥，免得漏出来）。
