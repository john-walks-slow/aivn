# 台词语气标记（对玩家隐藏）— 小结（261012）

用户原话：**「对话句支持语气标记（对用户隐藏）参考 /fish-audio（用简化版入剧作家提示词。包含常用 tag（包括 nsfw 后续常用的），无需太多复杂描述）」**。

## 做法

剧作家把 Fish Audio 的语气标记**直接写在 `<say>` 正文里**：

```xml
<say id="mio">[whispering] 别出声，他在隔壁。</say>
```

- 标记是**台词文本的一部分**：原样进谱系、原样进 TTS（`normalizeForTts` 不动方括号），
  位置即语义（句首管整句、句中只管后半句）。
- **只在上屏那一步剥掉**：core 新增 `stripToneTags(text)`；客户端 `ScriptLine` 同时留
  `text`（剥过，打字机/标点节奏/回顾都读它）与 `raw`（原文，改写框的初值用它，否则一改就把标记吃掉）。
  取自谱系节点的那条兜底路（`transcript.fromView`）也剥一次。
- 判「这一行有没有字可念」看剥过的那份：只有 `[sigh]` 的一行不合成。
- 翻译（`voiceLanguage`）与生图上下文（`recentScript`）都明确不放标记进去 / 保留标记原样。
- 给剧作家的说明只有**一章**（共享包 `packages/agent/src/prompt/stage-dsl.ts` 的 `TONE_RULES`，
  两个宿主引同一份）：语法一句 + 五组常用锚点词 + 位置/数量/放大器/圆括号四条规矩。

顺手退役了 `<say mood="…">`：它从来不驱动任何东西（不驱动立绘、不驱动配音、界面上早就不显示），
留着只会跟语气标记抢「怎么表达情绪」同一个问题（连 `.say-mood` 那条死 CSS 一起清了）。

## 为什么标记留在文本里，而不是提成 `tone` 属性

位置即语义——提成属性就只剩「整句一个语气」，句中的 `[gasp]` / `[pause]` 全丢；而且流式会撕裂标记
（`[whi` + `sper]`），解析期得做缓冲还得给「模型忘写 `]`」兜底。留在文本里，谱系/补生成/改写/翻译/
模型上下文这些路径一处都不用改。

## 事实依据

[`docs/freeform/261012-fish-audio-emotion-tags.research.md`](../../freeform/261012-fish-audio-emotion-tags.research.md)：
官方文档全量 + 本机 `s2.1-pro-free` 21 次实测 + 9 次 ASR 回读。三条影响设计的结论：
语法只有 `[方括号]`（`(小括号)` 是 S1 旧语法、S2.1 静默忽略且会被念出来）；
标记是**开放域**的（官方明说按普通文本处理，不存在可枚举白名单，所以引擎不校验词表）；
标记是**放大器不是覆盖器**（台词本身没情绪时几乎无效）——这一条直接写进了提示词。

## 验收

- 单测：core 的 `stripToneTags`（完整/多个/未闭合/中文括号/超长不误伤）；服务端「标记原样进 TTS、
  只有标记的一行不合成」；客户端「上屏剥掉、`raw` 保留、谱系兜底那条路也剥」。
- 端到端：假模型网关的剧本里写进 `[whispering]` 与 `[sigh]` 两行，真打 Fish 合成；
  浏览器实测断言「屏幕上任何可见文本都不含方括号」，并截图。
- `pnpm check:agent-contract`（改了提示词正文）。

## 遗留

- 引擎不校验标记词表（开放域无白名单），也不检测「这个标记到底有没有生效」——官方与社区都承认
  效果不稳定，靠的是台词本身有情绪 + 音色选择；提示词里已经把这两句写清。
- 只有 `<say>` 配音：旁白 / 内心独白 / 标题卡写标记没用（提示词里说明；上屏照样剥，免得漏出来）。
- 工作坊剧本、历史原文、回顾的改写框**保留原文**（作者面要能看见与编辑标记）；玩家演出的画面才隐藏。
