# 剧作家收成通用工具 · 用户验证要求

改动落在「剧作家怎么维护角色卡与记忆卡」这一条链上。**A、B 两组必须真跑一遍**（要真实模型、
真实演出），其余是回归。

前置：在 `.worktrees/generic-tools` 里起服务（`./scripts/init-worktree.sh` 之后
`./scripts/dev-worktree.sh`，端口现取），浏览器打开输出的地址，开一个新剧目。

## A 组：剧作家能自己建角色（本次核心）

1. 随便开一场戏，用自由输入让剧作家引出一个新角色（例如「一个叫小雨的转学生推门进来」）。
2. 期望：它调用 `write`（工具名就是 `write`，不是 `create_character`），路径形如
   `characters/xiaoyu.md`，内容带 frontmatter（至少 `name:`）。
   工坊「文件」页里能看到这张卡。
3. **这一轮的下一轮**，A 区（模型上下文里注入的角色表）里出现小雨，带完整人设。
   若它这一轮就已经用了 `xiaoyu` 这个 id，舞台名牌应显示「小雨」而不是 id。
4. 让小雨演几句带表情的台词（`<actor id="xiaoyu" expression="smile">`）→ 若它先生成了立绘，
   立绘正常上台。

## B 组：改既有卡不抹字段 + 引擎产物写不动

1. 先在工坊里给小雨配上音色（角色页选一个 `voiceId`），确认盘上那张卡有 `voiceId:` 一行。
2. 回到演出，让剧作家**改**小雨的人设（例如「把小晴改成在旧书店打工」）。
3. 期望：它先 `read` 再 `edit`（不是整篇 `write`）；改完后打开那张卡，
   **`voiceId:` 与 `sprites:` 都还在**，只有正文变了；小雨的配音照旧。
4. 让它试着改 `memory/arcs/` 下的文件（例如「把纪元摘要改一下」）。
   期望：写被拒，报错含「不在剧目可写范围」；盘上那份一个字节没动。

## C 组：记忆卡与召回

1. 让剧作家记一条世界设定（例如「记一下旧校舍三年前封了」）。
2. 期望：它 `write` 到 `memory/index/<分类>/<名字>.md`，首行 `# 标题`、次行一句话摘要；
   **下一轮** A 区的「记忆索引」里出现这一条。
3. 问它这条设定的细节 → 期望它用 `read_memory_detail` 或直接 `read` 那个文件答上来。

## D 组：回归（没被这次改动碰到、但共用同一批文件的东西）

1. 工坊文件页改任意一张记忆卡保存 → 立即生效，与改动前手感一致。
2. 让搭台助手改一个文件 → 一次重建，不是闪两次。
3. 从资源库导入一个带角色的素材 → 角色卡进剧目、角色表下一轮带上它。
4. 演出中调 `update_state`（好感度/旗标）→ 照旧生效；分岔/回退后这些值跟着回滚
   （**文件里的角色卡不跟着回滚**，这是设计如此）。

## 一处需要你动手的迁移（没有写兼容代码）

`play.json` 的 `agents.<role>.tools` 存的是**冻结的启用集**：只要你在某部剧目的 Agent 页动过
剧作家的工具开关，那份清单就写进文件了，之后服务端的默认值对它不起作用。

这次剧作家新增了 `read` / `write` / `edit` 三个工具，**这些老剧目里它们不会自动勾上**——
打开该剧目的 Agent 页 →「剧作家」→ 把「读文件 / 写文件 / 编辑文件」三个勾打上即可
（`create_character` / `write_memory` 两个旧 id 留在文件里无害，会被忽略）。

按项目约定不为它写迁移代码（上线前不做兼容层），所以这一条写在这里。
