## 三、实机记录

### 3.1 mock 剧目（`node scripts/mockLineage.mjs mocktree` 造 3 棵交替形态的树）

- Title 页三按钮：**开始新周目 / 继续（第 1 周目） / 周目（3）**，提示「已有 3 个周目，每个周目一棵独立故事树，互不覆盖。」
- 周目页 `#/play/mocktree/saves` 三张卡：名称 + `2 拍 · 09-07 00:33 更新` + 最后一句；当前档按钮变为「回到舞台」。
- 内联改名：`第 2 周目` → `手打完的周目`（Enter 提交）。随后 `cat meta.json` 确认 `id` 未变、名字已改、拍数与时间未动，且列表排序没有被顶到最前（按更新时间而非改名时间）。
- REST 全链路 curl：PATCH 改名 / PUT active / POST 新建（得「第 4 周目」，0 拍并成为当前）/ DELETE 非当前档（当前档不受影响）。
- 切档：进入第 3 周目后 `active.json` 变为该 id，舞台顶栏立即显示对应档名。

## 四、已知限制（有意不做，未向用户隐藏）

- **一个剧目同时只有一个 runtime**：切周目要 dispose + 重建正在跑的编排器，因此必须等当前这一拍结束（`await orchestrator.whenIdle()`）。语义上是「等这一拍演完」，不是丢弃。已写进周目页说明。
- **不写旧版数据迁移**：历史上落在剧目根目录的 `session.json` / `lineage.jsonl` 不会被自动收编为某个周目。项目尚未上线，按「不做旧版迁移」处理。
- **mock 剧本不重放**：`scripts/mockLineage.mjs` 造的 `session.json` 里 `runtime.events` 为空，而编排器恢复时是把 `runtime.events` 原样当作 WS 重放缓冲的，所以 mock 舞台只有「剧作家正在落笔…」没有历史行。这是 mock 造数据的局限，不是本功能的回归（demo 真实流程正常重放）。
