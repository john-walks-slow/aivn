# DSL v2 第二轮：景别运镜、动效、非人 sprite 与抽象层级

> 日期：2026-10-02 · 状态：设计输入，待定词
> 上游：[DSL v2 语法草案](261002-dsl-v2-proposal.research.md) · [引擎原语对照](261002-vn-engine-presentation-primitives.research.md) · [演出效果全集](261002-galgame-presentation-primitives.research.md)

## 0. 这一轮要解决的

上一版草案把 `at`（机位）、`enter/leave/action`（行为词）、`camera`（镜头）都定下来了。这一轮补四件事：

1. **景别 + 运镜融进 sprite 声明**——在 `expression` 之外再加一档。
2. **常见动效的声明式支持**——查清 gal 里最常见的那些，DSL 能给到什么程度。
3. **非人 sprite**（猫、机甲、悬空道具、飞行物体）的生成与展示。
4. **抽象层级**——人 / 非人 / 生成工具 / 展示 DSL 四处怎么统一最优雅。

## 1. 抽象层级：一个二分法不够，也不必做

### 1.1 先看「非人」到底缺了什么

把「人」和「非人」摆开逐项比，差异其实只有三处，而且都不是「贴不贴底」：

| 维度 | 人（立绘） | 非人 | 真的需要区分吗 |
|---|---|---|---|
| 头顶余量 | 有头，按 `top` 对齐留白 | 没有头 | 换个对齐基准即可 |
| 贴底 | 脚踩地 | 可能悬空、可能半埋 | 基准点可配 |
| 锚点 | 底部居中 | 中心 / 底边 / 自定义 | 锚点本来就是这个意思 |
| 大小 | 舞台高度的一个比例 | 同 | 无差异 |
| 位置 | 机位展开 | 同 | 无差异 |
| 差分 | 表情 | 状态（完好/破损/发光） | **同构**，都是换一张图 |

**结论**：没有「人 vs 非人」这个二分。真正要表达的是**这张图往哪儿对齐**。

### 1.2 唯一该有的开关：对齐基准（anchor）

Ren'Py 的 `anchor` 正是这件事的成熟解法（见引擎调研 §1.2）：位置与锚点分离，`anchor=(0.5, 1.0)` 表示「图的底边中心」对准 `pos`。于是：

- 人：锚点 = 底边中点
- 悬空物：锚点 = 中心
- 贴地小物件：锚点 = 底边中点（跟人一样）
- 从上方垂下：锚点 = 顶边中点

**同一套机制，四种摆放，不需要分类枚举。** DSL 里给一个词就够：

```
<actor id="cat" at="floor" anchor="center"/>
```

而绝大多数情况**连这个词都不用写**——见 §2 的自动默认。

### 1.3 生成侧：不该有「非人」这个参数

`generate_image` 现在有 `framing`。加非人支持时**不要**加 `kind="prop"` 之类——那会让工坊 agent 需要判断「这是人还是不是人」，而模型判断得并不准。

正确的做法是让**构图描述**跟着素材语义走，agent 只要照抄角色卡里的描述即可：

```
<actor id="cat" asset="cat" state="curled"/>
```

- `asset` 指向 play.json 里的一个素材条目（可以是 `characters/cat` 也可以是新的 `props/cat`）
- `state` 与人的 `expression` 完全同构——人换表情，物换状态

角色卡里 `appearance` 字段照常写外貌：「一只圆脸的橘猫，琥珀色眼睛」——和写人一样，生成路径一个字都不用改。

**唯一需要改的是提示词后缀**：人物立绘的后缀里有 `front-facing standing pose, neutral expression, both arms held slightly away from the body`（手要离开身体、轮廓要分得开），这对四脚动物是错的。需要一个「非人形」的构图后缀：

```
an animal or object standing, whole subject visible, nothing cropped by the frame,
clear empty white space around the subject
```

不给这层区分的话，生成猫会得到「猫站在那里的立绘」，实际上模型很容易处理；真正会出错的是**悬空物**（没有「站在」这回事），所以悬空物需要的是另一种后缀。→ 收敛成两条后缀：`standing`（人物/四足，站姿）与 `floating`（悬空物，居中留白）。

## 2. 位置：机位展开为主，手动为辅

### 2.1 编剧什么都不写是常态

用户原话：「指定五档位置都可能大部分场合多余，直接根据场上 sprite 数量自动分配空间」。

这个判断在调研里有支撑：Ren'Py 的默认 `xalign=0.5` 加「同 tag 替换不动 z 序」只解决**单人**，多人必须手写 `at left` / `at right`。**自动排布确实是行业空白**——Ren'Py 靠 `config.default_transform` 全局兜底，但那是一刀切的。

### 2.2 自动排布的规则（草案）

在场人数决定站位，**进场顺序决定落点**（先来的靠中间，符合直觉）：

| 在场人数 | 排布 |
|---|---|
| 1 | 居中 |
| 2 | 左右各半，**后进的在左**（主角视线方向） |
| 3 | 左中右等距 |
| 4 | 等距铺开，前后两层交错（避免四张图糊成一片） |
| 5 | 三前两后 |
| >5 | 警告，建议分场 |

**偏移量**：自动排布不是把人钉在 20%/50%/80% 这种死位置上，而是**按立绘实际宽度算**——相邻两张图之间留一个身位宽的缝，图本身有多宽就往外让多少。这样 5 个人同框不会挤成一坨。

### 2.3 手动覆盖

```
<actor id="lucy" at="left"/>          <!-- 站到左机位 -->
<actor id="lucy" at="2"/>            <!-- 站到第 2 号位（自动布局的编号） -->
<actor id="lucy" at="center"/>       <!-- 强制居中 -->
```

手动给过 `at` 的角色**退出自动排布**，其余的重新计算。这意味着「一个人手动靠左，另一个人自动」时，后者会去补右侧而不是跟着挤在中间。

## 3. 景别与运镜：加在哪一档

### 3.1 用户问的「在 expression 之外再加一档」

DSL 里角色已经有 `expression`（差分）。景别加在**同一张 `<actor>` 标签**上：

```
<actor id="lucy" expression="smile" shot="close"/>
```

而不是新开一个标签。理由：景别是**这一句此刻的演出状态**，不是场景级设置；新开标签会让「谁切了景别」这件事在剧本里变得不成组。

### 3.2 shot 与 camera 的分工

上一版草案里 `camera shot` 已经存在。现在要定的是：**景别到底走 actor 还是走 camera**。

调研给的答案（Ren'Py 的做法）是**两条路并存**：

| 手段 | Ren'Py 对应 | 语义 | 谁能写 |
|---|---|---|---|
| `shot`（挂 actor） | `transform zoom` | **这一张图**变大，变的是素材本身 | 编剧 |
| `camera`（挂整台） | `camera:` transform | 整个画面推拉，所有人一起变 | 编剧（少数场合） |

对 LLM 来说这个区分有实际意义：**「给她一个特写」写 `shot="close"`，「镜头拉远看全景」写 `camera shot="wide"`**。前者只影响她一个人，后者会影响所有人——这个区别剧本作者需要知道，引擎不该替他们猜。

**建议**：v2 保留两者，但 `actor` 上的 `shot` 是主力（十有八九的用例），`camera` 上的 `shot` 只在明确要动全员时用。

### 3.3 景别的取值

用户之前决定「生成时一律全身，别的景别靠镜头放大」。所以 `shot` 作用于**已有素材**，不触发重新生成：

| shot | 效果 | 典型用法 |
|---|---|---|
| `full` | 全身，标准站位 | 默认 |
| `half` | 腰部以上（裁掉腿） | 对话 |
| `close` | 胸部以上 | 情绪强调 |
| `extreme` | 头肩 | 冲击、告白 |

`half` / `close` / `extreme` 都只是**把立绘上移 + 放大**，下半部分被画面下沿切掉——和这轮刚定的 `.theater-sprite.framing-full { height: 132% }` 是同一个机制的连续档位。

## 4. 动效：声明式能覆盖多少

### 4.1 调研结论：gal 里真正高频的动效是很少的

把调研里各引擎的动效清单交叉后，按「gal 里出现频率」排序，**最高频的一批是**：

| 动效 | 出现频率 | 现状 |
|---|---|---|
| 立绘左右站位切换 | ★★★★★ | 已有（`at`） |
| 淡入淡出 | ★★★★★ | 已有（`enter/leave`） |
| 说话时轻微呼吸/摇摆 | ★★★★☆ | 缺 |
| 惊讶/害羞时整个人一抖 | ★★★★☆ | 草案有 `action="stagger"` |
| 说话者高亮、其余压暗 | ★★★★☆ | 缺 |
| 眨眼 | ★★★☆☆ | 缺（需要多张差分或 Live2D） |
| 脸红、汗滴等符号特效 | ★★★☆☆ | 缺 |
| 竖排文字逐字弹出 | ★★★☆☆ | 已有（打字机） |
| 背景缓慢推近（Ken Burns） | ★★★☆☆ | 草案的 `mood` 已含 |
| 画面震动 | ★★☆☆☆ | 草案有 `camera shake` |

**规律：出场、离场、换位、说话反馈这四类占了大头，且都能用「行为词」表达。** 越往下越是「锦上添花」。

### 4.2 声明式的边界（Ren'Py 反复印证的一条）

引擎调研 §1.8 的原文很关键：

> If two blocks try to change the same property at the same time, the behavior is unpredictable and should be avoided.

而引擎**不做检查**，只在文档里声明「未定义」。ATL 能做任意复杂的事，但复杂度由作者自觉兜着。

**对我们的含义**：DSL 的动效支持**不该追求表达力**，该追求「常用的一抓就有」。给一个自由参数（比如 `<actor id="x" shake="0.3"/>`）会让模型开始猜数字，而猜出来的数字全是坏的。**行为词 + 固定配方**是这个领域被验证过的选择——Ren'Py 的 `ease` / `easein` / `easeout` 之所以存在，就是为了让人不必碰曲线。

### 4.3 建议的动效面（草案）

分三层，都不加数字参数：

**第一层 · 常驻行为**（不需要写，引擎自动做）

```
<!-- 说这句台词的人轻微呼吸，其余静止 -->
```

这一层是「不做就不对」的东西，不该让编剧记。**但要克制**：呼吸做 WAAPI 无限循环，`.theater-sprite` 已有 `transition: opacity`，加呼吸要确认不打架。

**第二层 · 行为词**（写在 `<actor>` 上，一个词）

| 词 | 配方 | 用法 |
|---|---|---|
| `nudge` | 极轻的左右晃，3 次 | 「她有点动摇」 |
| `stagger` | 整个人一歪 + 回落 | 「被吓到」 |
| `jump` | 上弹回落 | 「兴奋」 |
| `nod` | 点头（上下位移一次） | 「同意」 |
| `bow` | 上身前倾 | 「鞠躬/道歉」 |
| `turn` | 横向压缩再展开（伪转身） | 「背过身」 |
| `shake` | 高频小幅抖动 | 「发抖/生气」 |
| `sway` | 缓慢左右摇摆 | 「放松/困倦」 |

`turn` 值得单独说：伪转身（横向压扁到 0 再展开）是 2D 立绘表现「转身」的业界通用做法，不需要第二张图。

**第三层 · 说话者高亮**（在 `<say>` 上，或自动）

```
<say id="lucy" highlight="others_dim"/>
```

最常见的是「说这句的人亮着，其他人不亮/压暗」。**这个默认就该开**——gal 里几乎每场都是这样，只是很少有引擎显式建模。可以做成 `<actor>` 的常驻状态而不必让编剧写。

### 4.4 明确不做的

- 粒子、Live2D、序列帧动画（用户已定，粒子与视频不进 v2）
- 任意时间轴 / 关键帧（Ren'Py 的 ATL 能做，但那是给「想写代码的人」用的）
- 变形、3D 旋转（`perspective` / `zrotate` 之类）

## 5. 生成侧的非人支持

### 5.1 角色卡加一个字段就够

```json
{
  "id": "cat",
  "name": "橘猫",
  "persona": "总趴在窗台上的橘猫，琥珀色眼睛，圆脸。",
  "spritePose": "floating"
}
```

`spritePose` 两个值：`standing`（默认，人物与四足）与 `floating`（悬空物，居中留白）。它只影响提示词后缀的选词，别的什么都不变。

**不给「非人」这个标签**——标签是给人看的分类，模型不需要它，引擎也不需要它。引擎只关心「这张图的构图基准是什么」。

### 5.2 出图画幅

非人 sprite 沿用 `framing` → 画幅的映射，但 **v2 出图一律全身**（用户 2026-10-02 定），所以非人也一样是 9:16。`framing` 字段对非人的意义只剩「这张图画布要多竖」——悬浮的行星用 1:1 更合适，但这属于后续镜头放大那批需求，先不动。

## 6. DSL 面的最终形态（草案）

标签集从 9 个扩到 10 个（只加一个）：

```
<scene bg=… bgm=… mood=…/>                    场景
<actor id=… expression=… shot=… at=… enter=… action=… anchor=… state=…/>   角色 / 非人
<camera focus=… shot=… shake=… letterbox=… reset/>                          镜头
<fx flash=…/>                                                               瞬时冲击
<cg id=… caption=…/>                                                        插图
<sfx src=… volume=…/>                                                       音效
<say id=… mood=… tone=… voice=/>                                             台词
<narrate>…</narrate>                                                        旁白
<thought id=…>…</thought>                                                    心声
<comment>…</comment>                                                        注释
```

**人物与非人在 `<actor>` 上同构**，差异全部落在可选属性上：

| 属性 | 人常用 | 非人常用 | 不写时 |
|---|---|---|---|
| `expression` | ✓ | — | 保持 |
| `state` | — | ✓ | 保持（人不用） |
| `anchor` | — | ✓ | 按 `framing` 定：全身→底边，胸像→中心 |
| `shot` | ✓ | ✓ | full |
| `at` | ✓ | ✓ | 自动排布 |
| `enter` / `action` | ✓ | ✓ | — |

也就是说：**没有 `kind="person"` / `kind="prop"` 这种二选一**。`expression` 和 `state` 甚至可以合并成一个属性（`variant`），语义都是「这张图用哪一张」——但那样会丢掉给模型的提示（模型需要知道哪个是表情、哪个是状态），所以分开更好。

### 6.1 给模型看的样子

```
<actor id="lucy" expression="smile" enter="walk"/>
<actor id="cat" state="curled" anchor="center" enter="pop"/>
<actor id="lucy" shot="close"/>
<actor id="lucy" at="left"/>
<actor id="lucy" action="stagger"/>
<actor id="lucy" leave="fade"/>
```

六行覆盖了「进场、换表情、特写、换位、反应、退场」——**没有一个数字、没有一条曲线名**。这是「面向 playwriter 而非代码编写员」这条约束的直接检验。

## 7. 待定清单

- `at` 的自动排布在 4–5 人同框时是否好看（需要实机验证）
- `anchor` 默认值怎么从 `framing` 推，还是干脆默认 `center` 让人物看着浮空一点？
- 常驻呼吸动效做不做——做了要确认不与 `transition: opacity` 打架
- 说话者高亮默认开还是默认关
- 非人 sprite 要不要单独的 `<prop>` 标签（初步判断：不要，并进 `<actor>`）
- `state` 与 `expression` 合并成一个 `variant` 的利弊
