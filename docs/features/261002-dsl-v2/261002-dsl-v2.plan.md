## 做了什么

| 能力 | 剧本怎么写 | 落在哪 |
|---|---|---|
| 运镜（景别） | `<actor id="x" shot="close"/>` | `--scale` × `transform-origin: top center` |
| 行为词（动效） | `<actor id="x" action="nod"/>` | 8 个 `@keyframes` 配方 |
| 非人主体 | `<actor id="cat" state="curled" anchor="center"/>` | `state` + `anchor` |
| 自动排布 | **什么都不写** | `layoutSprites()` 纯函数 |
| 默认过渡 | 什么都不写 | 站位/运镜/进出场全部带 transition |

`camera` 标签本轮不做（用户定）。

## 取景：三档，去掉胸像

`framing` 从 `full/half/bust` 改成 `full/half/square`：

| 档 | 画幅 | 用途 |
|---|---|---|
| full | 9:16 | 全身，标准站位 |
| half | 3:4 | 半身 |
| square | 1:1 | 非人主体（猫、道具、悬浮物） |

**去掉 bust 的理由**：胸像与半身只差一个躯干，而这个差别 `shot` 运镜本来就能补
（放大 + 上移），不必多一个生成档位。腾出来的 `square` 给了非人主体——
`full` 9:16 画一只猫是浪费，而 `bust` 这个名字对人以外的「头肩」不成立。

**存量数据不丢**：`bust` 降级到 `half`（`LEGACY_SPRITE_FRAMING`）而不是当非法值丢弃。
丢掉 = 一张胸像图悄悄按全身摆位画出来，错一整个躯干量级，用户看不出来发生了什么。
`parseCharacter` 的逐差分校验也改走 `framingOf`，与资源库那条路径一致。

## 提示词：通用后缀不分人形

用户定：**后缀只保留完全通用的约束**，不分人形/非人两套完整模板。
拆成三段（`playAssets.ts`）：

- `COMMON_TAIL` —— 画风与背景（纯白底、平涂、NOT 3D、no shadow/gradient/vignette）
- `POSE_TAIL` —— 人形专属（正脸站姿、双臂离开身体、头顶留白）
- `PROP_TAIL` —— 非人（整个主体完整入画、四周留白、不裁切）

`square` 走 PROP 不碰人形词。`NEUTRAL_LEAD` 也跟着分（原来是个
`framing === "bust" ? "bust" : "standing"` 的三元，给猫会出 "standing portrait"）。

**画幅不能省掉**：`framing` 同时决定画幅与舞台摆位，两者都不是提示词能传的。
画幅还必须在 Flow 支持的 5 档内（`2:3` 这类 Gemini 官方取值 Flow 静默退回 16:9）。

## 抽象层级：不分人 / 非人，分「对齐到哪儿」

没有 `kind="prop"` 这类二选一。四种摆放共用同一套机制，唯一开关是 `anchor`：

| 主体 | anchor | 效果 |
|---|---|---|
| 人 | `bottom`（默认） | 脚踩在舞台底边 |
| 悬空物 | `center` | 居中浮空 |
| 从上垂下 | `top` | 挂在上沿 |

`expression`（表情）与 `state`（状态）同构但**分开两个属性**——
合并成 `variant` 会丢掉给模型的提示（哪个是表情、哪个是状态）。

## 自动排布

`packages/core/src/play/spriteLayout.ts`：在场人数 → 站位，纯函数、可测。

- 1 人居中；2 人分居两侧（中间留空是舞台惯例）；3 人左中右；4 人以上加更靠边的档
- 候选池**由内到外**，人少时往中间站，人多时才挤到边上
- **手动钉过的档位从候选池里划掉**——不划的话主角占着 center 时，
  剩下那个自动角色会被分到 center，两个人叠在同一像素点
- 认不出来的 `at` 返回 null 走自动，**不猜不抛**（抛错会让人直接不登场）

web 侧每次 `<actor>` 指令都**重排全场**（`applyActorCue`），第二个人进场时第一个人自动让开。
**正在退场的不占排布名额**——算进去的话一个人退场后剩下的人永远按「两人同框」摆着。

## 默认过渡

用户定：shot 变化、登场退出、站位自动变化都默认带过渡。

| 变化 | 实现 |
|---|---|
| 换表情 | `opacity` 过渡（原有） |
| 换站位 / 换景别 | `transform` 过渡，`--move-ms: 380ms` |
| 登场 | `.entering` + `sprite-in` |
| 退场 | `.leaving` 软删除，淡出播完才摘 |

**水平位置从 `left` 改走 `transform`**（`--x`）：`left` 过渡每帧触发重排，
五六个立绘同框就是每帧一次全舞台重排；transform 只走合成层。

## 行为词

`packages/core/src/play/spriteAction.ts` + `app.css` 的 8 段配方。

不给自由参数（`shake="0.3"`）是 Ren'Py 调研的结论：模型会去猜，猜出来的全是坏的。
一个词对应一段调好的配方，剧本永远碰不到毫秒、曲线和 z-index。

`turn`（伪转身）用横向压扁到 0.12 再展开——立绘没有第二张背面图时的业界通法。

### 踩到的三个坑

1. **CSS 自定义属性不能被 `@keyframes` 平滑驱动**（按 token 替换、不可插值）。
   改用独立属性 `translate` / `scale` / `rotate`——四层变换各占一个，互不覆盖。
2. **animation shorthand 里两个裸数字相邻会让整条声明被静默丢弃**：
   `520ms ease 1 1`（delay 与 iteration-count）判不出哪个是哪个，
   `animation-name` 变 `none`，动画永远不启动且无任何报错。重播用的 nonce 必须写成时间。
3. **`--move-ms: 380` 少了单位**：`transition` 那条侥幸能用（被解析成 380s），
   `animation` 那条整条丢弃。同一批变量必须一起补单位。

前两个都是「不报错就是不生效」，靠读代码发现不了——是逐帧量 computed style 才抓到的。

## 说话者呼吸

`playback.view.actorId` 是当前说话人，立绘带 `.speaking` 常驻 0.4% 的呼吸。
默认开：gal 里几乎每场都是「说这句的人亮着、轻轻动着」，
写进剧本要模型每句都记得标记，漏一句就断了。

## 验证

- core 116 / server 397（3 跳过）/ web 101 全绿
- 三包 tsc 与 `pnpm -r build` 干净
- **实机逐帧测量**八个行为词：Web Animations API 采样 11 帧，
  确认各自动作特征正确（`turn` 横向压扁 1 → 0.12，`shake` 高频 ±1.6% 带倾，
