## 验证说明

- 验证对象：`dsh-aivn` 阶段 1（演出闭环）——剧作家预设、舞台视图、停止点、起剧目两条入口，
  以及检视（`261005-dsh-vn-plugin.review.md`，结论「条件准入」）三项阻塞 + 十二项建议的修复。
- 环境/前置条件：
  - 一个活着的 e2e 实例：`http://127.0.0.1:38543/?token=e2etest`（插件就是当前提交 `87207d0` 的构建）。
  - 仓库根已经种了一座带图的示例剧目（《舞台验收剧目》，一块背景 + 一张立绘），
    所以「新建会话 → 工作目录默认就是仓库根」这条路开箱能演。
  - **阈值**：后台的真实 LLM 端到端（选预设 → 开演 → 台词上屏 → 停止点 → 点选项 → 第二轮）
    已经由 `e2e/verify-stage.mjs` 跑绿（**14/14**，样式补全后重跑过），检视的三条阻塞路径另有
    `e2e/b1-probe.sh` 与一次真机式 HTTP 复核跑绿——**都不需要再手点一遍**。
    下面只列自动化测不到的部分。

- 验证对象：阶段 2 的两件事——①上下文注入与组装（`497edb3`）；②语音生成（`670e29b` 实施、

- 实例：`http://127.0.0.1:51784/?token=e2etest`（带 Fish Audio key 起的；仓库根已种示例剧目，
  缓存里已有 77 段合成好的音频）。
- **阈值**：下面两条已经由 e2e 跑绿，不需要再手点一遍：
  - `e2e/verify-injection.mjs` **11/11**——六个注入段与【状态】都在系统提示词里（从会话日志的
    `system/message` 事件取，不是看代码猜）。

    挂钩子）、语音总开关确实传到了宿主（抓客户端真实请求体）。

## 待跟进

- **N4（按会话回收）**：已修（`e7e3ad0`）。接 `agent/disposed` 收掉解析器、语音管线与轮状态；
  中枢的帧缓冲**故意保留**——会话关掉再打开时，舞台靠它把已经演过的部分重放出来。
- **N7（`file:` 依赖）**：`@aivn/core` / `@aivn/stage` 已移到 `devDependencies`（`e85a5da`）——
  它们被 esbuild 打进 `lib/`，运行时不需要，留在 `dependencies` 只会让消费者去解析一条本机路径。
  **还剩一件事**：新克隆 + `npm install` 仍然需要兄弟仓库 `stage-ai` 在位（重建才需要）。
  要彻底自包含，得先把这两个包发到 npm 再换成版本号——等用户决定。
- **B3（语音节奏）**：已定性（`99cc051`）。舞台是手动推进；自动模式下「这一行还在合成」现在
  也算 hold（封顶 8 秒）。手动模式下点太快的那一句会被丢弃，这是引擎本来的设计，已写进 README。
